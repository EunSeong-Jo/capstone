# 데모 시나리오 — "조 감독 시연"

> 목적: 지도교수 시연·발표에서 **비로그인 → 로그인/진단 → 화장대 등록(사진 스캔·챗봇) → 개인화 추천·대체품 → 장바구니 → 구매 → AI 피부관리·퍼스널 AI**의 한 줄기를 끊김 없이 보여준다.
>
> 최종 갱신: 2026-10-31 (실제 백엔드·DB·외부 API 연동 기준으로 다시 썼습니다. 이전 판은 `localStorage`·목업 기반이라 더 이상 맞지 않습니다)
>
> 화면 이름과 동작은 코드(`frontend/src/App.tsx`)와 [PROJECT_OVERVIEW.md](PROJECT_OVERVIEW.md) 5장 기준입니다. 버튼 문구는 개선 작업으로 바뀔 수 있으니 시연 전에 한 번 따라 해 보세요.

## 0. 실행 전제

데모는 **백엔드와 DB가 떠 있어야** 합니다(제품·대체품·궁합·주문이 모두 서버에서 옵니다).

| 방법 | 설명 |
|---|---|
| **운영 서버(권장)** | AWS Lightsail 컨테이너(`swappy`)가 화면과 API를 같은 주소로 서빙합니다. 브라우저로 열거나 Android 앱(APK)으로 접속 |
| **내 PC** | `docker compose up --build` → http://localhost:3000 (루트 `.env`에 `DATABASE_DSN` 필요). 절차는 [루트 README](../README.md) |

- 처음 접속하는 폰에는 로그인 화면 상단 배너에서 **APK를 내려받아** 설치합니다(`/swappy.apk`).
- 외부 API 키가 없으면 해당 기능만 대체 동작합니다: LLM 키 없음 → 챗봇이 DB 기반 폴백 답변, OCR 키 없음 → 사진으로 찾기가 503이고 제품명 검색으로 안내, 사진 분석은 허용 계정만 실호출([backend/README.md](../backend/README.md) "얼굴 사진 AI 분석").
- 시연을 처음부터 다시 하려면 새 계정으로 가입하거나, 데모 계정을 쓰고 브라우저 저장소(`swappy:*` 키)를 지웁니다.

### 테스트 계정 — 가입 직후 화면용

`테스터1`(`test1@gmail.com`)·`테스터2`(`test2@gmail.com`)는 인삿말·QnA·진단·**선물 받는 쪽** 화면을 보여 주기 위한 계정입니다. 데모 선물의 받는 사람이 이 두 계정입니다.

### 로그인 방법

1. **이메일 로그인** — 위 표의 이메일 + 비밀번호 (시연 기본)
2. **데모 퀵버튼** — 로그인 화면의 "데모 계정" 패널. **기본으로 숨겨져 있고**, 로고를 7번 연달아 누르면 기기에서 켜고 끌 수 있습니다(`VITE_DEMO_PANEL=on` 빌드는 기본 표시)
3. **게스트** — "로그인 없이 둘러보기"

### 운영(AWS) 시연용 조은성 계정 — 모든 기능이 보이게 채워 둔 데이터

```bash
python3 scripts/seed_demo_account.py                      # 로컬 서버에 API로 채움 (여러 번 돌려도 안전, 모자란 것만 더함)
python3 scripts/seed_demo_account.py --base https://... --allow-prod --password '...'   # 운영: 플래그가 있어야만
docker exec -i -e PYTHONPATH=/app -w /app swappy_backend python - < scripts/seed_demo_analysis.py   # 16항목 사진 분석 1건
python3 scripts/seed_delivered_orders.py                  # 후기 작성용 배송완료 주문 (페르소나별)
```

운영에는 덤프 복원이 아니라 **앱과 같은 API 경로**로 채웁니다(덤프가 커서 연결이 끊겨 바꿨습니다). 반품 주문은 배송완료 단계(주문 30분 뒤)에서만 되므로 처음 돌리면 주문만 만들고 30분 뒤 다시 돌릴 때 반품합니다.

| 기능 | 데이터 |
|---|---|
| 화장대 | 4개 카테고리를 모두 포함한 10개 안팎(무료 한도 20개 안), 대체품·더 잘 맞는 제품·액상 리필(토너·세럼)이 나오는 제품 |
| 예산 | 5~10만원 |
| 주문 | 배송완료 5건 + **취소 1건 + 반품 1건** |
| 후기 | 배송완료 주문 제품에 3건 + 작성 가능한 제품 |
| 찜·장바구니·스캔 기록 | 찜·장바구니·스캔이 각각 몇 개씩 |
| 선물 | 보낸 선물 2건 (받는 사람: 테스터1·2) |
| AI 피부관리 | 구독 계정 + 16항목 분석 1건 |

화면이 5개 제품만 골라 대체품을 묻는다(`useSwapSuggestion`의 `MAX_SEEDS`) — 홈의 '리필·다른 용량'은 그날 뽑힌 제품에 따라 나오지 않을 수 있다. 항상 보려면 화장대에서 해당 제품을 눌러 대체품을 봅니다.

## 3. 백엔드 시드 (선택 — 논문/DB 확인용)

"통합 DB에 진단까지 들어간 실사용자"를 보여주려면:

```bash
# 백엔드 venv, .env에 DATABASE_DSN 설정된 상태에서
python scripts/seed_quiz.py                   # 진단 문항 6개 (없으면 먼저)
python scripts/seed_test_users.py --dry-run   # 계획만 출력
python scripts/seed_test_users.py             # users/profiles/diagnoses/diagnosis_ranks 적재 (멱등)
```

- `personas.json`을 그대로 읽어 프론트와 **같은 사람**을 DB에 심고, 화장대에는 보유 화장품을 넣는다.
- `users`(bcrypt 해시) · `profiles`(skin_type·scores·budget) · `diagnoses` + `diagnosis_ranks`(1~3순위).
- 이메일이 이미 있으면 갱신하고, 진단 기록은 사용자별로 지운 뒤 재삽입한다. 공용 DB에 쓰므로 돌리기 전에 팀에 알린다.

## 4. 시연 전 알고 있어야 할 한계

- **결제는 흉내**다(PG 미연동). 구독도 실결제가 아니라 데모 활성화이고, 선물은 기록만 남는다(수락·전달 없음).
- **사진 분석은 허용 계정만 실제로 외부(Perfect Corp)를 부른다.** 그 밖의 계정은 표본 계정의 저장된 결과를 보여 준다(비용 보호). 표본 계정에 분석이 없으면 503이고 화면은 QnA로 이어진다.
- **OCR은 앞면 촬영 전제**다. 뒷면은 인식되지 않고, 카탈로그에 없는 제품은 "찾는 제품이 없어요"로 끝난다. 계정당 하루 3회·전체 하루 15회 한도라 시연 직전에 연습으로 소진하지 말 것.
- 챗봇은 LLM 키가 막히면 **DB 폴백**으로 답한다(`mode: "fallback"`). 도구 호출(제품 카드·담기 제안)은 로그인 사용자만.
- 퍼스널 AI는 신호가 쌓여야 보인다: 성분 취향은 제품 3개 미만이면 꺼져 있고, 피부 변화 리포트는 분석이 2건 필요하다. 시연 계정은 미리 채워 둔다.
- 날씨·케어 문구는 **서울 기준**이다.
