## 1. 제품 개요

### 1.1 한 줄 요약

회원가입 시 피부타입 진단 QnA로 사용자 프로필을 구축하여 8가지 피부타입 캐릭터(옹달샘·물개·수부지·화산·사막·인절미·유리구슬·메밀묵) 중 하나를 부여하고, 메인 화면에서 해당 프로필에 맞는 화장품 세트·조합을 추천한다. 추천 제품 상세 페이지에서는 AI가 전성분을 분석해 성분 유사도가 높은 대체품을 매칭하며, 예산 입력 시 그 안에서 최적의 화장품 루틴 구매 가이드를 제시한다. 텍스트·이미지 검색, AI 챗봇 상담, 가성비 비교까지 한 화면에서 제공하며, 화장품을 시작으로 영양제·패션 등 다양한 도메인으로 확장 가능한 범용 구조를 지향한다.

### 1.2 배경 및 문제 정의

화장품 소비자는 다양한 이유로 어려움을 겪는다.

**기존 사용 제품이 있는 사용자:**
- 현재 쓰는 제품이 너무 비싸서 성분은 비슷하면서 더 저렴한 '저렴이'를 찾고 싶을 때
- 특정 성분에 알레르기가 생겨서 해당 성분만 빠진 유사 제품이 필요할 때
- 브랜드가 리뉴얼하면서 기존 포뮬러가 바뀌었을 때
- 해외 제품의 국내 대체품을 찾고 싶을 때

**기존 사용 제품이 없거나 화장품 입문자 (v1.8 신규 타겟):**
- "내 피부에 뭐가 맞는지 모르겠다" — 어디서부터 시작해야 할지 모름
- "예산 10만원으로 기초 화장품을 어떻게 구성해야 하나?" — 구매 가이드 부재
- 화장품 정보 과잉 속에서 "나에게 맞는 것"을 골라내기 어려움
- 다른 사람 추천을 따라 샀다가 자신의 피부에 안 맞아 실패한 경험

**핵심 문제점:**

- 화장품 구매 시 성분을 고려하는 소비자 비율이 약 70%에 달하지만, '내 피부 타입에 맞춰 제품을 추천하고 + 비슷한 대체품까지 자동으로 찾아주는' 통합 서비스는 부재
- 성분 관련 검색량이 전년 대비 3배 이상 증가하고 있음에도 해결책이 부재
- 기존 뷰티 플랫폼(화해, 글로우픽 등)은 성분 정보·리뷰는 제공하지만, **개인 프로필 기반 추천 + 성분 기반 대체품 매칭 + 예산 가이드의 통합 흐름**은 미지원
- 화장품 입문자가 신뢰할 수 있는 시작점(가이드)이 부재 → 광고성 콘텐츠와 인플루언서 의존도가 높음
- 성분 리스트를 보더라도 각 성분의 역할·위험성을 이해하기 어려워, 전문적인 가이드가 부재함

### 1.3 솔루션

**메인 플로우 — 프로필 기반 제품 추천:**
회원가입 단계에서 피부타입 진단 QnA를 수행하여 8가지 캐릭터 타입 중 하나로 사용자를 분류한다. 메인 화면에서는 해당 타입에 최적화된 화장품 세트·조합·단품을 추천하며, 신규 가입 직후에는 환영 팝업을 통해 "내 피부 타입을 위한 추천 세트"를 즉시 노출한다. 예산을 입력하면 그 금액 안에서 스킨/로션/에센스 등 루틴을 구성하는 구매 가이드를 제공한다(P1a).

**서브 플로우 — 성분 유사도 대체품 매칭:**
프로필 추천으로 노출된 제품 또는 사용자가 검색한 제품의 상세 페이지에서, 해당 제품과 성분 구성이 가장 흡사한 대체 제품 TOP 3를 자동 추천한다. 텍스트 검색·이미지 인식 진입점은 그대로 유지하여 "이미 쓰는 제품의 대체품" 니즈도 동시에 해결한다.

**확장 흐름:**
- 회원가입 시 도메인(화장품/영양제/패션 등) 다중 선택 UI 제공 (v1.8 P0: UI만, v1.8 P2: 실제 기능)
- AI 챗봇으로 성분 상담 (P1)
- 날씨·기후 데이터 연동으로 계절·환경 맞춤 추천 (P2)

### 1.5 도메인 확장 전략

"swappy"의 핵심 엔진(속성 벡터화 → 유사도 계산 → 매칭, 그리고 프로필 → 속성 매핑 → 추천)은 도메인에 독립적으로 설계한다. 화장품은 첫 번째 적용 사례이며, 동일한 파이프라인 구조로 다음 도메인에 확장할 수 있다.

| 도메인 | 비교 속성 | 프로필 매칭 축 | 데이터 소스 (예시) |
|--------|----------|---------------|------------------|
| **화장품 (v1)** | 전성분 리스트, 성분 함량 순서 | 피부타입 8타입 | 식약처 API, 올리브영 크롤링 |
| 영양제 (v2, P2) | 영양성분, 함량, 권장량 | 건강 목적(피로/수면/면역 등) | 식약처 건강기능식품 DB |
| 패션 (v2, P2) | 소재 혼용률, 핏, 스타일 태그 | 체형/스타일 선호 | 무신사·지그재그 크롤링 |
| 향수 (v3) | Top/Middle/Base 노트 | 선호 노트 카테고리 | Fragrantica 데이터 |

**v1.8 단계 도메인 선택 UI:**
회원가입 흐름에서 "관심 도메인" 다중 선택 화면을 제공한다(화장품/영양제/패션 등). 화장품 외 도메인은 선택 시 "추후 오픈 예정" 안내로 처리되며, 사용자 관심도 데이터로만 수집된다(P0). 실제 기능은 P2에서 도메인 어댑터 패턴으로 확장한다.

이를 위해 백엔드는 **도메인 어댑터 패턴**으로 설계하여, 새 도메인 추가 시 데이터 수집기(Collector)와 속성 파서(Parser), 프로필 매칭 룰(ProfileMapper)만 구현하면 유사도 엔진·추천 엔진·프론트엔드를 재사용할 수 있도록 한다.

### 2.1 프로젝트 목표

| 구분 | 목표 |
|------|------|
| **기능 목표** | 회원가입 + 피부타입 QnA → 프로필 기반 제품 추천(메인) → 상세 페이지 대체품 TOP 3(서브) → 가성비 비교 → 구매 링크 End-to-End 플로우 완성 (P0) + AI 챗봇·예산 가이드·성분 필터링 (P1a) |

### 2.2 핵심 성공 지표 (KPI)

| 지표 | 목표치 | 측정 방법 | 우선순위 |
|------|--------|----------|---------|
| 회원가입 전환율 | Soft-gate 노출 후 가입 완료 30% 이상 | 추적 로그(둘러보기 → 가입 유도 노출 → 가입 완료 퍼널) | P0 |
| 피부타입 QnA 완주율 | 가입 시작 사용자의 80% 이상 완주 | QnA 시작 / 완료 이벤트 비교 | P0 |
| 피부타입 매칭 만족도 | "내 피부 타입과 일치한다" 응답 75% 이상 | 추천 결과 페이지 5점 척도 미니 설문 | P0 |
| 프로필 추천 클릭률 (CTR) | 메인 화면 추천 카드 노출 대비 클릭 25% 이상 | 노출/클릭 이벤트 로그 | P0 |
| 성분 유사도 Hit Rate | TOP 3 내 정답 포함률 80% 이상 | 화해 앱 유사 제품 쌍을 Ground Truth로 활용한 자동 평가 | P0 |
| 이미지 검색 제품 인식률 | 정면 사진 기준 85% 이상 | 테스트 이미지셋 100장 기준 정확도 측정 | P0 |
| DB 수록 제품 수 | MVP 2,000개 → 최종 5,000개 이상 | 식약처 API + 크롤링 데이터 집계 | P0 |
| 평균 응답 시간 | 검색/추천 후 3초 이내 결과 표시 | 애플리케이션 로그 측정 | P0 |
| 예산 가이드 만족도 (P1a) | "추천 조합이 합리적이다" 응답 70% 이상 | 베타 테스트 설문 (5점 척도) | P1a |
| 챗봇 응답 적절성 (P1) | 사용자 평가 만족 70% 이상 | 베타 테스트 설문 (5점 척도) | P1a |

**KPI 측정 구체 계획:**

- **피부타입 매칭 만족도 평가 방법:**
  1. **소스 1 — 베타 테스트 자가 평가:** 베타 사용자 20~30명이 QnA 응답 후 결과 캐릭터에 대해 "나의 피부와 일치 정도"를 5점 척도로 응답 (목표: 평균 3.75/5 이상)
  2. **소스 2 — 외부 진단 비교:** 가능한 경우 화해·뷰티앱의 피부타입 진단 결과와 비교하여 핵심 축(건성/지성, 민감성 유무) 일치율 70% 이상 확인
  3. **반복 측정:** QnA 문항·진단 룰 개선 시마다 동일 평가 재실행

- **Hit Rate Ground Truth 구축 방법:**
  1. **소스 1 — 뷰티 커뮤니티 자동 수집 (목표 30쌍):** 파우더룸·네이버 카페·인스타에서 "○○ 저렴이", "○○ 대체품" 키워드로 크롤링하여 게시글 내 언급된 제품명 쌍을 자동 추출 (정규식 + 제품 DB 매칭)
  2. **소스 2 — 성분 겹침 기반 자동 추출 (목표 20쌍):** DB 내 동일 카테고리에서 상위 5개 성분 중 3개 이상 겹치는 제품 쌍을 스크립트로 자동 생성
  3. **자동 검증 기준:** 수집된 50쌍에 대해 "INCI 기준 전체 성분 겹침률(Jaccard Index) ≥ 60%"를 충족하면 정답으로 자동 확정. 이 기준은 유사도 알고리즘과 다른 독립적 메트릭이므로 순환 평가(circular evaluation)를 방지함
  4. **평가 방식:** 스크립트로 제품 A 입력 → TOP 3에 제품 B 포함 여부 자동 체크. 전 과정 자동화되어 알고리즘 변경 시마다 1분 내 재실행 가능
  5. **확장:** DB 확대 시 소스 2에서 자동 생성되는 쌍이 증가하므로, Ground Truth도 자동으로 확장됨
- **이미지 인식 테스트셋:** 올리브영 베스트셀러 100개 제품의 정면 패키지 이미지를 직접 촬영. "정면/측면/어두운 환경" 3가지 변형 포함 (총 300장).
- **베타 테스트 설문:** 9월 베타 기간 중 테스터 20~30명 모집 (학과 내 + 뷰티 관심 지인), 각 기능별 5점 척도 만족도 + 자유 피드백 수집.

## 3. 타겟 사용자

### 3.1 페르소나 A — 트렌드 민감형 (20대 여성)

- **키워드:** SNS 뷰티, 색조 덕후, 가성비 추구
- **니즈:** 고가 브랜드 립스틱과 색감·성분이 비슷한 저렴이 버전을 찾고 싶음
- **Pain Point:** 커뮤니티 검색과 블로그 리뷰에 의존해야 하며, 광고성 콘텐츠와 실제 후기를 구분하기 어려움
- **핵심 사용 기능:** 이미지 검색(SNS 사진 속 제품 식별), 가성비 비교표, **상세 페이지 대체품 매칭**
- **메인 진입 경로:** 게스트 모드 → 이미지/텍스트 검색 → (Soft-gate) 가입 유도

### 3.2 페르소나 B — 피부 건강 중심형 (30대 직장인)

- **키워드:** 민감성 피부, 성분 분석, 안전 우선
- **니즈:** 현재 사용 중인 스킨케어와 성분이 가장 유사하면서 특정 자극 성분은 빠진 안전한 대체품이 필요
- **Pain Point:** 전성분 직접 비교는 전문 지식이 필요하고 시간이 많이 소요됨
- **핵심 사용 기능:** 피부 타입 진단(유리구슬 타입 등), 성분 유사도 분석, 성분 필터링, AI 챗봇(P1 이후)
- **메인 진입 경로:** 가입 → 피부타입 QnA → 메인 추천 → 대체품 비교

### 3.3 페르소나 C — 화장품 입문자 (v1.8 신규, 20대 초반·대학생/사회초년생)

- **키워드:** 화장품 입문, 어디서 시작할지 모름, 예산 한정
- **니즈:** "내 피부에 맞는 기초 화장품을 10만원 이내로 한 번에 사고 싶다"
- **Pain Point:**
  - 지금까지 부모님·친구가 추천한 걸 따라 썼지만 내 피부에 맞는지 확신 없음
  - 어떤 단계(스킨/로션/에센스/크림)부터 시작해야 할지 모름
  - 광고와 리뷰가 너무 많아 정보 과잉
- **핵심 사용 기능:** 회원가입 + 피부타입 QnA, 프로필 기반 추천 세트 팝업, 예산 기반 구매 가이드(P1a)
- **메인 진입 경로:** 가입 → 피부타입 QnA → 환영 팝업("당신은 옹달샘 타입! 추천 세트 확인") → 예산 입력 → 구매 가이드

### 3.4 공통 니즈

- 광고성 블로그가 아닌 AI 기반 객관적·검증된 추천
- 정보 탐색 시간 단축 및 구매 확신 제공
- 성분에 대한 쉬운 설명과 전문적인 상담
- **자신의 피부 특성에 대한 직관적 이해 (캐릭터 메타포 활용)**

## 4. 사용자 시나리오

### 4.1 시나리오 0 — 신규 사용자 온보딩 (v1.8 신규, 메인 플로우)

> **"화장품을 처음 제대로 시작해보려는 22세 대학생, 자신의 피부 타입을 모름"**

| Step | 화면 | 사용자 행동 | 시스템 반응 |
|------|------|-----------|-----------|
| 1 | 스플래시 | 앱 첫 실행 | 서비스 소개 후 "가입하기 / 둘러보기" 선택지 노출 |
| 2 | 회원가입 | "가입하기" 선택 → 이메일/소셜 로그인 | 계정 생성, 약관 동의 |
| 3 | 도메인 선택 | 관심 도메인 다중 선택 (화장품/영양제/패션) | 화장품 외는 "추후 오픈" 안내, 선택값은 프로필에 저장 (P0) |
| 4 | 피부타입 QnA | 7~10문항 질문 응답 (세안 후 당김·번들거림·트러블 빈도·민감도·고민 등) | 각 응답을 가중치 점수로 환산 |
| 5 | 결과 화면 | 캐릭터 결과 확인 (예: "당신은 옹달샘 타입!") | 8타입 캐릭터 일러스트 + 특징 설명 + 추천 성분/주의 성분 안내 |
| 6 | 추천 팝업 | "내 타입을 위한 추천 세트 확인하기" 버튼 | 옹달샘 타입 맞춤 화장품 세트 3종(스킨/로션/에센스) 팝업 |
| 7 | 메인 화면 | 팝업 닫기 또는 세트 보기 후 메인 진입 | 프로필 기반 큐레이션 메인 화면 표시 |

**Soft-gate 분기:**
- Step 1에서 "둘러보기" 선택 시 → 가입 없이 게스트 모드로 메인 화면 진입 (단, "오늘의 인기 제품" 등 일반 큐레이션만 노출, 개인화 X)
- 게스트가 "내 피부 타입 맞춤 추천 받기" 등 개인화 기능 클릭 시 → 가입 유도 모달

### 4.2 시나리오 A — 프로필 기반 추천에서 대체품 탐색 (v1.8 메인 시나리오)

> **"가입 후 추천받은 토너의 성분이 마음에 들지만 가격이 부담스러운 25세 사용자"**

| Step | 화면 | 사용자 행동 | 시스템 반응 |
|------|------|-----------|-----------|
| 1 | 메인 | 프로필 기반 추천 카드 중 한 제품 탭 | 제품 상세 페이지로 이동 |
| 2 | 제품 상세 | 전성분, 가격, 별점 확인 | 동일 페이지 하단에 "이 제품과 비슷한 대체품" 섹션 노출 |
| 3 | 분석 실행 | "대체품 더 보기" 버튼 클릭 | AI가 성분 유사도 분석 실행 (로딩 인디케이터) |
| 4 | 결과 목록 | TOP 3 대체품 확인 | 유사도 순 정렬, 상위 3개 제품 카드 표시 |
| 5 | 비교 화면 | 가성비 비교표 확인 | ml당 가격, 주요 성분 순위, 별점 비교 |
| 6 | 구매 연동 | 원하는 제품 선택 | 올리브영·쿠팡 등 외부 구매 페이지로 이동 |

### 4.3 시나리오 B — 텍스트/이미지 검색으로 대체품 탐색 (기존 사용 제품 보유 사용자)

> **"SNS에서 본 립스틱 사진으로 제품을 찾고, 비슷한 저렴이를 추천받는 20대 사용자"**

| Step | 화면 | 사용자 행동 | 시스템 반응 |
|------|------|-----------|-----------|
| 1 | 메인 검색 | 카메라 아이콘 탭 → 갤러리에서 사진 선택 또는 직접 촬영 | 이미지 업로드 후 분석 시작 |
| 2 | 이미지 분석 | 분석 대기 | AI가 이미지에서 제품 패키지·텍스트(브랜드명, 제품명)를 인식하여 DB 매칭 |
| 3 | 매칭 확인 | 식별된 제품 확인 (복수 후보 시 선택) | "이 제품이 맞나요?" 확인 화면, 전성분 표시 |
| 4 | 분석 실행 | '대체품 찾기' 클릭 | 시나리오 A의 Step 3~6과 동일 |

**엣지케이스:**
- 이미지 인식 실패 시 → "제품을 식별하지 못했습니다. 제품명을 직접 입력해 주세요." 안내 + 텍스트 검색으로 Fallback
- 복수 후보 매칭 시 → 후보 제품 2~3개를 카드로 표시, 사용자가 선택
- 게스트 사용자가 검색·대체품 탐색 → 가입 없이 사용 가능 (Soft-gate)

### 4.4 시나리오 C — 예산 기반 구매 가이드 (P1a, v1.8 신규)

> **"옹달샘 타입 진단을 받은 후 '10만원으로 기초 풀세트를 구성하고 싶은' 입문자"**

| Step | 화면 | 사용자 행동 | 시스템 반응 |
|------|------|-----------|-----------|
| 1 | 메인 | "예산으로 구매 가이드 받기" 버튼 탭 | 예산 입력 화면 진입 |
| 2 | 예산 입력 | 금액 입력 (예: 100,000원) + 원하는 카테고리 선택 (스킨/로션/에센스 등) | 예산 + 프로필 매칭 알고리즘 실행 |
| 3 | 추천 조합 | 예산 내 최적 조합 1~3개 안 확인 | 각 안에 대해 총액·구성 제품·매칭 성분 표시 |
| 4 | 조합 비교 | 안 비교 (성분 매칭률, 별점, 잔여 예산) | 추천 사유 표시 ("옹달샘 타입에 부족한 보습 성분을 충족") |
| 5 | 일괄 구매 | 원하는 안 선택 → "외부 쇼핑몰로 이동" | 판매처별로 묶어 외부 페이지 일괄 이동 |

### 4.5 시나리오 D — AI 챗봇으로 성분 상담 (P1a)

> **"대체품 결과를 받은 후, '나이아신아마이드가 뭐야?' '민감성 피부에 이 제품 괜찮아?'를 물어보는 사용자"**

| Step | 화면 | 사용자 행동 | 시스템 반응 |
|------|------|-----------|-----------|
| 1 | 하단 챗봇 | 챗봇 버튼 탭하여 패널 오픈 | 챗봇 인터페이스 슬라이드 업 |
| 2 | 대화 | "나이아신아마이드가 뭐야?" 입력 | 성분 DB 기반으로 역할, 효능, 주의사항을 쉬운 말로 설명 |
| 3 | 맥락 연동 | "방금 추천받은 2번 제품, 민감성 피부에 괜찮아?" | 현재 조회 중인 제품의 성분 정보와 **사용자 프로필(유리구슬 타입)**을 연동하여 맞춤 답변 |
| 4 | 추가 탐색 | "그러면 히알루론산 들어간 수분크림 중에 가성비 좋은 거 추천해줘" | 조건 기반 필터링 후 제품 추천 카드 삽입 |

**챗봇 대화 범위:**
- 개별 성분의 역할·효능·부작용 설명
- 현재 조회 중인 제품의 성분에 대한 맥락적 질답
- **사용자 프로필(피부타입) 기반 맞춤 안내 (v1.8 강화)**
- 제품 비교 질문 (예: "A제품이랑 B제품 중 어떤 게 더 보습력 좋아?")
- 대체품 조건 검색 (예: "파라벤 없는 수분크림 추천해줘")

**챗봇 대화 범위 밖 (안내 후 리다이렉트):**
- 의료 진단 ("이 트러블이 아토피인가요?") → "피부과 전문의 상담을 권장드려요"
- 서비스와 무관한 일반 대화 → 서비스 기능 안내로 자연스럽게 유도

### 4.6 서브 시나리오

- **성분 필터링 검색 (P1a):** 특정 성분 제외(알레르기 유발 성분 등) 조건을 설정한 뒤 대체품 검색
- **카테고리 내 비교:** "수분크림" 카테고리에서 내 제품과 가장 성분이 비슷한 제품 탐색
- **프로필 재진단:** 마이페이지에서 피부타입 QnA 재실행 (계절 변화·피부 변화 반영)

## 5. 기능 요구사항

### 5.1 P0 — MVP 핵심 기능 (7월 말 완성 목표)

> 이것만 있으면 서비스의 핵심 가치(프로필 기반 추천 메인 + 대체품 매칭 서브)를 검증할 수 있다.

#### F1. 회원가입 및 사용자 온보딩 (v1.8 신규)

**계정 생성:**
- 이메일 + 비밀번호 가입 (P0 우선)
- 소셜 로그인(Kakao, Google) (P0 여유 시 / P1a 보장)
- 약관 동의, 개인정보 처리 동의

**Soft-gate 정책:**
- 첫 실행 시 "가입하기 / 둘러보기" 선택지 제공
- 게스트 모드에서도 검색·대체품 탐색·제품 상세 확인 가능
- 개인화 기능(프로필 추천·예산 가이드·챗봇 프로필 컨텍스트) 사용 시점에 가입 유도 모달 노출

**관심 도메인 선택 UI:**
- 가입 직후 "관심 있는 도메인을 선택하세요" 화면 (다중 선택)
- 옵션: 화장품(활성), 영양제·패션 등(비활성 + "추후 오픈 예정" 라벨)
- 선택값은 user_profile.interested_domains에 저장 (P2 도메인 확장 시 활용)

#### F2. 피부타입 진단 QnA (v1.8 신규)

**문항 구성:**
- 7~10개 문항 (예: 세안 후 당김 시간, 번들거림 부위, 트러블 빈도, 민감 반응 경험, 모공·홍조 등)
- 각 문항은 객관식 4~5지선다, 가중치 점수 환산

**8가지 결과 타입 (캐릭터 기반):**

| 캐릭터 타입 | 핵심 특성 | 추천 성분 방향 |
|------------|----------|---------------|
| 수분팡팡 옹달샘 타입 | 수분·유분 균형, 자극 적음 (이상적 피부) | 가벼운 보습 유지 |
| 반질반질 물개 타입 | 지성, 번들거림, 모공 신경 | 살리실산, 가벼운 제형, 논코메도제닉 |
| 겉바속촉 수부지 타입 | 수분 부족 지성 (속건조+겉번들) | 히알루론산 + 가벼운 유분 조절 |
| 울긋불긋 화산 타입 | 트러블·홍조·염증 잦음 | 시카, 판테놀, 진정 성분 / 자극 성분 회피 |
| 바스락 사막 타입 | 극건성, 당김 강함 | 세라마이드, 시어버터, 고보습 |
| 말랑말랑 인절미 타입 | 건성·탄력 양호 | 보습 + 안티에이징 보조 |
| 조심조심 유리구슬 타입 | 민감성, 자극에 즉각 반응 | 저자극 인증, 무향, 무알코올 |
| 얼룩덜룩 메밀묵 타입 | 색소침착·잡티·톤 불균형 | 나이아신아마이드, 비타민C, 미백 라인 |

> **주:** 캐릭터별 정확한 진단 룰과 가중치는 5월 후반 DB 구축 단계에서 화장품 도메인 자료(화해·뷰티 도서·피부과 전문의 자문 등)를 참고하여 확정한다. v1.8에서는 캐릭터 컨셉과 추천 방향만 우선 정의한다.

**결과 화면:**
- 캐릭터 일러스트 + 타입명 + 1줄 요약
- 추천 성분 / 주의 성분 안내
- "내 타입 추천 세트 보기" CTA

#### F3. 프로필 기반 메인 화면 추천 (v1.8 신규)

**메인 화면 큐레이션:**
- 사용자 피부타입에 매칭되는 제품 카드 그리드
- 섹션 구성: "내 타입 추천 세트" / "내 타입에 인기" / "내 타입에 부족한 영양분"
- 게스트 모드에서는 "오늘의 인기 제품" 등 일반 큐레이션으로 대체

**추천 세트 팝업 (가입 직후):**
- 피부타입별로 사전 큐레이션된 화장품 조합(예: 스킨/로션/에센스 세트) 1~3개 팝업 노출
- 팝업에서 "전체 보기" 또는 "닫기" 선택 가능

**추천 알고리즘 (P0):**
- 룰 기반: 피부타입 → 추천 성분 태그 → 해당 성분 함량 높은 제품 + 별점 상위 정렬
- 동일 카테고리 내 다양성 보장 (한 브랜드 최대 1~2개)
- 신규 사용자 대상 콜드 스타트 문제는 룰 기반으로 해결 (P2에서 협업 필터링 도입 검토)

#### F4. 제품 검색 (텍스트 + 이미지) [기존 v1.7 F1]

**텍스트 검색:**
- 제품명 텍스트 입력을 통한 검색
- 자동완성 및 검색 제안 기능 (pg_trgm 기반 퍼지 매칭)
- DB에서 해당 제품의 전성분 데이터 조회 및 표시

**이미지 검색:**
- 카메라 촬영 또는 갤러리 이미지 업로드
- AI가 이미지에서 제품 패키지의 텍스트(브랜드명, 제품명)를 OCR로 추출
- 추출된 텍스트를 DB와 매칭하여 제품 식별
- 복수 후보 시 사용자 선택 화면 제공
- 인식 실패 시 텍스트 검색으로 Fallback 안내

#### F5. 성분 유사도 분석 엔진 [기존 v1.7 F2]

- 전성분 데이터를 벡터화 및 유사도 계산 (다중 알고리즘 비교 실험 후 최적 방법 적용, 7.6.3 참조)
- 동일 카테고리 내 필터링 후 유사도 상위 3개 대체품 반환

#### F6. 대체품 TOP 3 결과 화면 (서브 기능으로 재배치) [기존 v1.7 F3]

- 제품 상세 페이지 내 "비슷한 제품" 섹션으로 진입
- 유사도 점수(%) 표시
- 제품 이미지, 브랜드명, 제품명, 가격 정보 카드 형태로 제공
- 각 제품 클릭 시 상세 비교 화면으로 이동

#### F7. 가성비 비교표 [기존 v1.7 F4]

- ml당 가격 산출 및 비교
- 주요 성분 순위 비교 (원본 제품 vs 대체품)
- 한 화면에서 최대 3개 제품 동시 비교

#### F8. 만족도 지표 (별점 기반) [기존 v1.7 F5]

- 크롤링 수집된 별점의 평균 점수를 만족도 지표로 활용
- 리뷰 건수 함께 표시하여 신뢰도 판단 근거 제공
- 대체품별 별점 평균을 결과 카드 및 비교표에 반영

#### F9. 구매 링크 연결 [기존 v1.7 F6]

- 올리브영, 쿠팡 등 외부 쇼핑몰 구매 페이지 연동
- 최저가 정보 제공

**F10. 예산 기반 구매 가이드 (v1.8 신규)**

- 사용자가 예산 금액 + 원하는 카테고리(스킨/로션/에센스/크림 등)를 입력

  - 총액 ≤ 예산

**F11. AI 챗봇 [기존 v1.7 F7]**

- 화면 하단 플로팅 버튼 → 탭 시 챗봇 패널 슬라이드 업

- 제품 비교 질문 지원, 조건 기반 필터 검색을 대화로 수행
- 대화 중 제품 추천 시 인터랙티브 카드 삽입
- 서비스 범위 밖 질문 시 적절한 안내 메시지 반환

**F12. 성분 필터링 [기존 v1.7 F8]**

### 6.2 Domain Adapter 패턴 상세

도메인 확장을 위해 백엔드의 데이터 수집·속성 파싱·프로필 매칭 로직을 어댑터로 분리한다.

```
BaseAdapter (추상 클래스)
├── collect_data()           # 데이터 소스에서 원시 데이터 수집
├── parse_attributes()       # 원시 데이터 → 표준 속성 벡터로 변환
├── get_product_info()       # 제품 기본 정보 반환
├── get_price_info()         # 가격/용량 정보 반환
└── map_profile_to_tags()    # (v1.8 신규) 사용자 프로필 → 추천 속성 태그

CosmeticsAdapter(BaseAdapter)    ← v1 구현
├── collect_data()           → 식약처 API + 올리브영 크롤링
├── parse_attributes()       → 전성분 리스트 → TF-IDF 벡터
├── get_product_info()       → 브랜드, 제품명, 카테고리, 이미지
├── get_price_info()         → ml당 가격, 판매처별 가격
└── map_profile_to_tags()    → 피부타입(예: 옹달샘) → 추천 성분 태그
```

유사도 엔진(SimilarityEngine)과 추천 엔진(RecommendationEngine)은 어댑터가 반환한 표준 벡터·태그를 입력받아 동작하므로 도메인에 독립적이다.

### 7.6 성분 유사도 분석 엔진 — 기술 상세 [기존 v1.7 7.4와 동일, 번호만 갱신]

#### 7.6.1 데이터 전처리

```
원시 성분 데이터 (식약처 API)
  │
  ▼
① 성분명 정규화
   - 동의어 통합: "정제수" = "Water" = "Aqua"
   - 영문/한글 매핑 테이블 구축 (INCI Name 기준)
   - 대소문자·공백·특수문자 정리
  │
  ▼
② 성분 순서 가중치 부여
   - 화장품 전성분 표시법: 함량 많은 순으로 기재
   - 상위 성분에 높은 가중치 → 위치 기반 가중 TF-IDF
   - 예: 1번째 성분 가중치 1.0, 2번째 0.95, ... 감소 함수 적용
  │
  ▼
③ 벡터화
   - 각 제품의 성분 리스트 → TF-IDF 벡터 (차원: 전체 고유 성분 수)
   - 사전 계산하여 DB에 벡터 캐싱
```

#### 7.6.2 유사도 계산

```
사용자가 제품 A 선택 (메인 추천 카드 또는 검색)
  │
  ▼
제품 A의 캐싱된 TF-IDF 벡터 로드
  │
  ▼
전체 제품 벡터와 코사인 유사도 일괄 계산
  │  (numpy 행렬 연산으로 배치 처리)
  │
  ▼
동일 카테고리 필터링 (스킨케어끼리, 색조끼리)
  │
  ▼
유사도 상위 3개 제품 반환
```

**성능 최적화 전략:**

- 전체 제품 TF-IDF 매트릭스를 scipy sparse matrix로 메모리에 상주시켜 실시간 계산
- 제품 수 2,000개(MVP) 기준, 코사인 유사도 계산 예상 소요 시간: ~20ms
- Redis에 최근 검색 결과 캐싱 (TTL 24시간)

#### 7.6.3 TF-IDF 적용 시 한계 및 보완 전략

화장품 성분 리스트에 TF-IDF를 적용할 때 구조적 한계가 존재한다.

**한계 1: TF(Term Frequency)가 무의미함**
- 일반 문서에서 TF는 "단어가 문서 내에서 몇 번 등장하는가"를 측정하지만, 화장품 성분 리스트에는 동일 성분이 중복 등장하지 않아 TF 값이 전부 1이 됨
- 결과적으로 IDF(희귀 성분일수록 가중치 높음)만 작동하게 됨

**한계 2: 성분 순서(함량 비율)를 본질적으로 반영하지 못함**
- 화장품 전성분은 함량 많은 순으로 기재되므로, 1번째 성분과 20번째 성분은 함량 차이가 큼
- 위치 기반 가중치로 보완하지만, 가중치 감소 함수의 최적 형태를 사전에 알기 어려움

**보완: MVP 단계에서 다중 알고리즘 비교 실험 수행**

MVP 개발 시 아래 3가지 알고리즘을 동일 데이터셋에 적용하고, Ground Truth(유사 제품 쌍 50쌍)에 대한 Hit Rate를 비교하여 최적 알고리즘을 선정한다.

| 알고리즘 | 원리 | 장점 | 단점 |
|----------|------|------|------|
| 위치 가중 TF-IDF + 코사인 유사도 | 성분별 위치 가중치 × IDF로 벡터화 후 코사인 거리 | 구현 간단, scikit-learn 활용 | TF 무의미, 가중치 함수 튜닝 필요 |
| Weighted Jaccard Similarity | 공통 성분 수 / 전체 성분 수 + 위치 가중치 | 직관적, 성분 중복 없는 데이터에 적합 | 성분 의미 유사도 반영 불가 |
| 순서 기반 거리 (Rank-Biased Overlap) | 성분 순서 리스트 간 순위 일치도 측정 | 함량 순서를 직접 비교 | 성분 종류가 다르면 비교 어려움 |

실험 결과에 따라 단일 알고리즘 또는 앙상블(가중 평균) 방식을 선택한다. 이 실험 결과는 졸업작품 발표 시 "알고리즘 선정 근거"로 활용할 수 있다.

#### 7.6.4 알고리즘 고도화 로드맵

| 단계 | 방법 | 기대 효과 | 시기 |
|------|------|----------|------|
| **MVP (P0)** | 3종 알고리즘 비교 실험 후 최적 선정 (TF-IDF / Jaccard / RBO 중) | 데이터 특성에 맞는 알고리즘 근거 확보 | 5월 후반 실험, 6월 적용 |
| **개선 (P1b)** | 앙상블 또는 임베딩 기반 전환 (실험 결과에 따라 결정) | MVP 대비 Hit Rate 10%p 개선 목표 | 9월 (여유 시) |
| **고도화 (P2)** | 성분 임베딩 (Word2Vec/FastText) 또는 GNN | 의미적 유사도 반영 | 10월~ |

| **보완 방안** | 화해·올리브영 데이터로 교차 검증 및 보완 |

**초기 수집 현실적 일정:**

- 일 1,000건 제한 × 1개 인증키 = 2,000개 제품 수집에 최소 2일 소요
- 단, API 응답 중 카테고리 필터링이 불가할 경우, 전체 데이터에서 카테고리별 필터 필요 → 수집량 증가
- **리스크:** 공공데이터포털 인증키 복수 발급 가능 여부 사전 확인 필요 (정책 변경 가능성)
- **대안:** 공공데이터포털 "대용량 파일 다운로드" 서비스가 있으면 API 대신 일괄 다운로드 우선 시도

#### 8.1.2 올리브영 — 제품 정보·가격·리뷰·이미지

| 항목 | 내용 |
|------|------|
| **수집 대상** | 제품명, 브랜드, 가격, 용량, 이미지, 카테고리, 별점, 리뷰 건수 |
| **수집 방법** | Selenium + BeautifulSoup (동적 페이지 대응) |
| **수집 범위** | MVP: 스킨케어/베이스메이크업 약 2,000개 → 이후 확대 |
| **수집 주기** | P0: 초기 1회 수동 수집 + 필요 시 재실행 / P1: 가격 주 1회, 별점 월 1회 자동 |
| **Rate Limiting** | 요청 간 2~5초 랜덤 딜레이, User-Agent 로테이션 |

**크롤링 현실적 고려사항:**

- 올리브영은 Anti-bot 대응이 강화되는 추세 → Selenium Headless + undetected-chromedriver 조합 필요
- 크롤링 차단 시 대안: 올리브영 공식 API 제공 여부 조사, 쿠팡/네이버 쇼핑에서 동일 제품 정보 수집
- 2,000개 제품 × 요청 간 3초 = 약 100분 소요, 네트워크 오류·재시도 감안 시 1일 작업으로 산정
- **robots.txt 사전 확인 필수:** 크롤링 불가 경로가 있을 경우 해당 데이터는 다른 소스로 보완

#### 8.1.3 네이버 쇼핑 API — 최저가·판매처

| 항목 | 내용 |

| **호출 제한** | 일 25,000건 |

## 9. 유사·경쟁 서비스 분석

| 서비스 | 강점 | 한계 | swappy 차별점 |
|--------|------|------|----------------|
| **화해** | 방대한 DB, 성분 사전, 피부 타입별 필터링 | 성분 기반 대체품 자동 매칭 없음, 가성비 비교 없음, 프로필 기반 메인 큐레이션 약함 | 피부타입 8캐릭터 + 전성분 벡터화 + 자동 매칭 + 가성비 비교 (P0) |
| **글로우픽** | AI 리뷰 요약, 다양한 카테고리 | 성분 유사도 비교 없음, 대체품 추천 없음 | 성분 기반 대체품 + 가성비 원스톱 |
| **OnSkin (해외)** | 바코드 스캔 즉시 분석, 안전도 기반 추천 | 안전도 기준 대체 (유사도 아님), 한국 DB 부족 | 이미지 인식 + 유사도 매칭 + 한국 제품 특화 |
| **무신사 (의류 도메인)** | 도메인 특화 큐레이션, 개인화 추천 | 도메인 락인 | 통합 도메인 확장 가능 구조 (P2) |

**핵심 차별점 요약:**

MVP(P0) 단계 차별점 (v1.8 재정의):
1. **8타입 캐릭터 기반 피부타입 진단 + 프로필 메인 큐레이션** — 직관적이고 친근한 피부타입 표현으로 화장품 입문자 진입 장벽 최소화 (신규 차별점)
2. **멀티모달 검색** — 텍스트 검색 + 이미지 촬영/업로드로 제품을 찾는 두 가지 경로 제공
3. **성분 기반 대체품 자동 매칭** — AI가 전성분을 벡터화하여 가장 비슷한 제품을 자동 추천 (메인 흐름의 서브로 통합)
4. **가성비 원스톱 비교** — 성분 유사도 + 가격 + 만족도를 한 화면에서 제공

서비스 전체(P1~P2 포함) 차별점:
5. **예산 기반 구매 가이드 (P1a)** — 예산 입력만으로 입문자가 신뢰할 수 있는 풀세트 구성 즉시 제시
6. **AI 챗봇 통합 (P1)** — 프로필을 인지하는 맞춤 상담
7. **날씨 기반 맞춤 추천 (P2)** — 오늘의 날씨·환경에 맞는 제품을 매일 추천
8. **도메인 확장 가능 구조** — 화장품을 넘어 영양제·패션 등으로 확장 가능한 범용 엔진

## 10. 기대 효과

### 10.1 사용자 관점

MVP(P0) 기대 효과:
- **신규 사용자 진입 동기 부여 (v1.8 핵심):** 회원가입만으로 "내 피부 타입을 알 수 있는 재미있는 진단" + "맞춤 추천 세트" 즉시 제공
- **진입 장벽 최소화:** 제품 사진만 찍으면 바로 대체품 탐색 시작 — 제품명 몰라도 OK
- **정보 탐색 비용 절감:** 커뮤니티·성분표 수동 비교 없이 AI가 즉시 추천·대체품 발굴
- **스마트한 가성비 소비:** 고가 브랜드 대신 성분 유사한 합리적 가격 제품 발굴

P1 이후 추가 기대 효과:
- **입문자 구매 결정 지원 (P1a):** 예산 가이드로 "10만원으로 기초 라인 시작" 같은 구체적 결정 지원
- **성분 이해도 향상 (P1):** AI 챗봇이 프로필을 인지한 채로 어려운 성분명을 쉬운 말로 설명
- **맞춤형 일상 케어 (P2):** 날씨 기반 추천으로 매일 달라지는 피부 컨디션에 선제 대응

### 10.2 비즈니스 관점

- **신규 사용자 유입·전환 증가:** 8타입 캐릭터의 SNS 공유성으로 바이럴 잠재력 확보
- **신규 비즈니스 모델 창출:** 제휴 마케팅(올리브영, 쿠팡 등 구매 링크 수수료)
- **고객 이탈 방지 및 구매 전환율 증대:** 제품 탐색 단계에서 바로 구매로 연결, 입문자에게 신뢰할 가이드 제공
- **마케팅 효율화:** 사용자 프로필·검색·구매·챗봇 대화 데이터 기반 트렌드 인사이트 확보
- **데이터 자산화:** 도메인별 사용자 관심도 분포 등 추후 도메인 확장 시 우선순위 판단 자료로 활용

## 17. 날씨 기반 제품 추천 — 기술 상세 (P2)

### 17.1 개요

사용자의 현재 위치 날씨·환경 데이터를 실시간으로 연동하여, 오늘의 피부 컨디션에 맞는 제품을 추천하는 기능. **사용자 프로필(피부타입)과 결합하여 "옹달샘 타입에게 자외선이 강한 오늘 추천하는 선케어" 같은 이중 조건 추천**으로 고도화한다 (v1.8 통합). 메인 화면 상단에 "오늘의 추천" 배너로 노출한다.

### 17.2 날씨-성분 매핑 룰

| 날씨 조건 | 피부 영향 | 추천 성분/카테고리 | 데이터 소스 |
|----------|----------|-----------------|-----------|
| 자외선 지수 높음 (8 이상) | UV 손상 위험 | 선케어, 비타민C, 나이아신아마이드 | 기상청 생활기상지수 API |
| 습도 30% 이하 (건조) | 수분 손실 | 히알루론산, 세라마이드, 고보습 크림 | 기상청 단기예보 API |
| 습도 80% 이상 (습함) | 유분 과다·모공 | 가벼운 제형, 살리실산, 논코메도제닉 | 기상청 단기예보 API |
| 미세먼지 나쁨 이상 | 모공 막힘, 자극 | 클렌징, 진정 성분(시카, 판테놀) | 에어코리아 API |
| 기온 영하 (동절기) | 피부 장벽 약화 | 세라마이드, 시어버터, 오일 제품 | 기상청 단기예보 API |
| 기온 30°C 이상 (하절기) | 피지 과다 | 워터 베이스 제형, 매트 제품 | 기상청 단기예보 API |

### 17.3 시스템 플로우

```
사용자 위치 (브라우저 Geolocation API)
  │
  ▼
위치 → 가장 가까운 관측소 매핑
  │
  ▼
기상청 API 호출 (단기예보 + 생활기상지수)
  │  + 에어코리아 API (미세먼지)
  │  캐싱: 동일 지역 1시간 TTL
  │
  ▼
날씨 조건 파싱 (기온, 습도, UV, 미세먼지)
  │
  ▼
날씨-성분 매핑 룰 + 사용자 프로필 매핑 룰 교집합
  │  → 오늘 추천 성분/카테고리 도출
  │
  ▼
해당 성분을 포함한 제품 중 별점 높은 순으로 추천
  │  (기존 유사도 엔진과 별도, 단순 필터 + 정렬)
  │
  ▼
메인 화면 "오늘의 추천" 배너에 3개 제품 카드 표시
```

### 17.4 데이터 소스

| API | 제공 데이터 | 호출 제한 | 갱신 주기 |
|-----|----------|----------|----------|
| 기상청 단기예보 API | 기온, 습도, 강수 확률 | 일 10,000건 | 3시간마다 |
| 기상청 생활기상지수 API | 자외선 지수, 불쾌지수 | 일 10,000건 | 6시간마다 |
| 에어코리아 API | 미세먼지(PM10/PM2.5) | 일 500건 | 1시간마다 |

### 17.5 셀링 포인트

- **차별화:** 기존 뷰티 앱에는 없는 "오늘 날씨에 맞는 제품 추천" 기능으로 매일 접속할 이유를 제공
- **리텐션:** 날씨는 매일 바뀌므로, 사용자가 습관적으로 앱을 열어보는 DAU 유도 효과
- **크로스셀링:** 기존에 검색하지 않던 카테고리(선케어, 클렌징 등)로 자연스럽게 노출 확대
- **계절 마케팅 연동:** 환절기·황사 시즌 등 특정 기간에 맞춤 추천으로 구매 전환율 증대

## 18. 용어 정의 (Glossary)

| 용어 | 정의 |
|------|------|
| **INCI Name** | International Nomenclature of Cosmetic Ingredients. 화장품 성분의 국제 표준 명칭 |
| **전성분** | 화장품에 포함된 모든 성분을 함량 순서대로 나열한 리스트. 식약처 규정에 따라 표시 의무 |
| **TF-IDF** | Term Frequency–Inverse Document Frequency. 문서 내 단어의 중요도를 측정하는 통계적 방법 |
| **코사인 유사도** | 두 벡터 간의 방향 유사성을 -1~1 사이 값으로 측정하는 방법. 1에 가까울수록 유사 |
| **Jaccard Similarity** | 두 집합의 교집합 크기를 합집합 크기로 나눈 유사도. 0~1 범위 |
| **KoBERT** | SKTBrain에서 개발한 한국어 특화 BERT 모델. 한국어 텍스트 분류·감성 분석에 활용 |
| **OCR** | Optical Character Recognition. 이미지 내 텍스트를 기계가 읽을 수 있는 문자로 변환하는 기술 |
| **EWG 등급** | Environmental Working Group에서 부여하는 화장품 성분 안전 등급 (1~10, 낮을수록 안전) |
| **Context Injection** | 챗봇 대화 시 현재 화면의 제품·성분 정보 및 **사용자 프로필**을 System Prompt에 자동 주입하는 기법 |
| **RAG** | Retrieval-Augmented Generation. 외부 데이터를 검색하여 LLM 응답의 근거로 활용하는 기법 |
| **Hit Rate** | 추천 결과 TOP N 안에 정답이 포함되는 비율. 추천 시스템의 핵심 정확도 지표 |
| **Ground Truth** | 알고리즘의 정확도를 평가하기 위한 정답 데이터셋 |
| **SSE** | Server-Sent Events. 서버에서 클라이언트로 실시간 데이터를 스트리밍하는 HTTP 프로토콜 |
| **pg_trgm** | PostgreSQL의 트라이그램 유사도 검색 확장. 오타·부분 매칭을 허용하는 퍼지 검색 지원 |
| **RBO** | Rank-Biased Overlap. 두 순서 리스트 간의 순위 일치도를 측정하는 유사도 지표. 상위 순위에 더 높은 가중치 부여 |
| **JWT (v1.8)** | JSON Web Token. 사용자 인증 정보를 토큰 형태로 안전하게 전달하는 표준. Access/Refresh 토큰 페어 운용 |
| **Soft-gate (v1.8)** | 즉시 회원가입을 강제하지 않고, 개인화 가치가 발생하는 시점에 가입을 유도하는 UX 패턴 |
| **콜드 스타트 (v1.8)** | 신규 사용자/제품에 대해 행동 데이터 부족으로 개인화가 어려운 문제. 룰 기반·사전 큐레이션으로 완화 |
| **피부타입 8캐릭터 (v1.8)** | 옹달샘·물개·수부지·화산·사막·인절미·유리구슬·메밀묵의 8가지 캐릭터로 한국 사용자 피부 특성을 직관적으로 표현하는 자체 분류 체계 |
