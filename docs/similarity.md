## 왜 IDF가 필요한가

전성분에서 **상위 6종이 사실상 모든 제품에 들어 있다.**

| 성분 | 출현율 |
|---|---|
| 글리세린 | 85% |
| 정제수 | 84% |
| 1,2-헥산다이올 | 81% |
| 부틸렌글라이콜 | 80% |
| 에틸헥실글리세린 | 66% |
| 소듐하이알루로네이트 | 51% |

단순 교집합으로 세면 아무 두 제품이나 이 여섯 개가 겹쳐서 비슷해 보인다.
**IDF는 이 성분들의 가중치를 0에 가깝게 만들어 계산에서 사실상 지운다.**
그러면 판테놀·마데카소사이드·디에칠헥실부타미도트리아존처럼 실제로 제형을
가르는 성분만 점수를 결정한다.

`backend/tests/test_similarity.py::test_common_ingredients_score_low`가 이
경계를 지킨다. 이 테스트가 깨지면 추천이 정제수를 근거로 아무거나 고르게 된다.

성분 문서빈도 분포 — 실제 제품에 붙은 성분은 사전 25,923종 중 **6,403종**이다.

| DF | 성분 수 |
|---|---|
| 1건 | 2,818 |
| 2–5 | 1,591 |
| 6–20 | 994 |
| 21–100 | 664 |
| 101–500 | 279 |
| 501–2,000 | 51 |
| 2,000+ | 6 |

## 방식: tfidf와 hybrid (jaccard·rbo는 제거)

`similarities`의 PK가 `(product_id, similar_id, method)`라 방식별 결과를 나란히 둘 수 있다.

| method | 무엇을 보나 | 상태 |
|---|---|---|
| `hybrid` | 역할 가중 tfidf 0.65 + 성분 **기능 프로필** 코사인 0.35 | **기본값.** 아직 적재 안 된 환경은 API가 tfidf로 대신한다 |
| `tfidf` | IDF 가중 코사인 | 기준선·대체. 공통 성분(`sharedIngredients`)도 이쪽 계산을 쓴다 |

hybrid는 `ingredient_functions`(성분별 기능 9종·역할·플래그, `data/seed/ingredient_functions/`)를 쓴다.
- **역할 가중 tfidf (0.65)**: 활성 1.0 · 에몰리언트 0.6 · 기타 0.35 · 계면활성/점증 0.25 · 용매/방부 0.2 · 오염 이름 0, 라벨 없음 0.6
- **기능 프로필 (0.35)**: 제품이 보습·진정·미백… 중 무엇을 얼마나 가졌는지의 분포(앞 성분일수록 크게, 확신도 1은 제외),
  자외선 차단제는 무기(징크·티타늄)/유기 유형 축을 더한다
- **제형 일치 (0.20)**: 이름에서 스틱·쿠션·패드·시트·오일·폼·워터·세럼… 제형을 뽑아 같으면 가산(모르면 중립)
- **같은 제품의 변형 접기**: 용량·매수만 다른 제품은 후보에서 하나로 접는다(기준 제품의 변형은 프론트가 '다른 용량'으로 보여 주므로 3개까지 남김)
- **옵션형 묶음의 형제 제외**: 같은 옵션 그룹(`products.option_parent_id`)의 옵션은 서로의 후보로 올리지 않고(화면의 옵션 드롭다운으로 고른다), 다른 제품의 후보에는 그룹당 최고점 하나만 남긴다(`dedupe_topk(families=…)`)
- **판정 보정**: `data/seed/similarity_curated.csv`(AI 성분 전문가가 직접 0/1/2로 판정한 1,443쌍, goods_no 키)가 있는 쌍은
  0점 −0.15, 2점 +0.10으로 보정해 다시 정렬한다. 대상은 평가 시드 80개와 조회(리뷰)가 많은 제품 60개다.
- 응답의 `sharedFunctions`: 두 제품이 함께 가진 기능(양쪽 모두 활성/에몰리언트 근거가 있는 것만)

### 평가 (`scripts/eval_similarity.py`)

정답 데이터가 없어 시드 80개(카테고리 고르게) × 후보 풀 843건을 성분 전문가 관점에서 0/1/2로
판정했다(`data/eval/similarity_gold.csv`, 판정자는 AI 1명). 풀은 모든 설정의 상위 5개를 합친 것이고,
풀 밖 후보는 0으로 세므로 방식 간 비교용이다.

| 방식 | nDCG@10 | 정밀도@5(=2) | 1위 점수 | 5위 점수 | 결정 |
|---|---|---|---|---|---|
| tfidf | 0.635 | 0.330 | 0.45 | 0.20 | 유지(기준선·대체) |
| hybrid v1 (역할 가중 + 기능 프로필) | 0.678 | 0.343 | 0.64 | 0.46 | 이전 기본값 |
| + 변형 접기 | 0.663 | 0.338 | 0.64 | 0.46 | **채택**(아래 참고) |
| + **제형 일치 0.20** | **0.799** | **0.468** | 0.65 | 0.49 | **채택, 현재 기본값** |
| 제형 0.10 / 0.35 | 0.799 / 0.790 | 0.420 / 0.468 | | | 0.20이 최적 근처 |
| 가중 0.5/0.5, 0.8/0.2 | 0.787 / 0.777 | | | | 0.65/0.35 유지 |
| 자외선 유형 축 제거 | 0.797 | 0.463 | | | 효과는 작지만 선케어에서 +0.009라 유지 |
| 성분 임베딩 항 (e5-small) | 0.800~0.801 | 0.468 | 0.67~0.72 | 0.53~0.60 | **제거** |
| jaccard / rbo | 0.603 / 0.344 | 0.273 / 0.153 | | | **제거** |

> **2026-11-01 재측정 주석.** 위 표는 옵션 분해(2026-10-25, `bba8212`) 이전 DB 기준이다. 분해 뒤 같은 스크립트·같은 판정으로 다시 돌리면
> 기본값(hf20)이 **0.711**, tfidf가 0.549다 — 상위 5개 후보의 19%(395칸 중 75칸)가 판정이 없는 새 옵션 행이라 0점으로 세어진다.
> 그래서 `pool --seeds 0`으로 미판정 후보 163쌍을 뽑아 판정을 보강했다(판정 1,006건, 보강분 163건은 Claude가 같은 기준으로 판정, 사람 검수 없음).
> 보강 뒤 nDCG@10은 tfidf 0.613 · hybrid_v1 0.647 · **hf20 0.765**로, 방식 간 순위(제형 일치가 가장 큰 개선)는 그대로이고 절대값은 표(0.799)보다 낮다.
> 남은 차이(0.034)는 판정자가 다른 데서 생겼을 수 있다(보강분은 같은 상품의 다른 옵션을 1로 매긴 경우가 많다). 독립 평가는 `docs/evaluation/`의 test 판정을 본다.

- 가장 큰 개선은 **제형 일치**다(0.678 → 0.799). 선케어 0.651 → 0.858, 클렌징 0.604 → 0.814. 판정 풀에서 스틱↔크림,
  오일↔폼 같은 불일치가 가장 흔한 0점 원인이었다.
- **변형 접기**는 nDCG를 약간 낮춘다(0.678 → 0.663). 같은 제품의 다른 용량이 모두 "대체 가능(2)"으로 판정돼 정답 집합에
  들어 있기 때문이다. 목적은 후보 자리를 다양하게 쓰는 것이라(예: 마스크팩 1매/4매/5매가 상위 5칸 중 3칸을 차지하던 문제) 유지한다.
- **임베딩**은 nDCG를 올리지 못했다(+0.001, 오차 수준). 점수만 부풀려(5위 0.49 → 0.60) 임계값을 흔들 뿐이라 제거했다.
  화학명 임베딩이 약하고, 기능 라벨이 이미 같은 정보를 준다. 스크립트·산출물도 삭제했다.
- rbo는 점수만 높고 순위 품질이 가장 낮았다(1위 평균 등급 0.77). jaccard는 IDF가 없어 흔한 성분에 끌려갔다.
- 판정 보정은 같은 판정으로 평가하면 순환이라 지표에 넣지 않았다. 판정이 없는 제품에는 영향이 없다.
- 화면의 "비슷함" 임계값(`SIMILARITY_HIGH`)은 hybrid 분포에 맞춰 30 → 55로 다시 잡았다(시드당 약 4개가 초록).

> 아래 점수 분포·겹침 수치는 jaccard·rbo가 있던 시절의 측정이라 역사 기록으로만 남긴다.

<details><summary>이전 3방식 측정 기록</summary>

`similarities`의 PK가 `(product_id, similar_id, method)`라 세 결과를 나란히
적재해 비교할 수 있다. **정답 데이터가 없으므로 눈으로 보고 정한다.**

| method | 무엇을 보나 | 성격 |
|---|---|---|
| `tfidf` | IDF 가중 코사인 | **기본값.** 흔한 성분을 죽인다. 가장 엄격 |
| `jaccard` | 단순 교집합 / 합집합 | 기준선. IDF가 무슨 일을 하는지 보여주는 대조군 |
| `rbo` | 표기 순서까지 (p=0.9) | 함량 순서를 반영. 가장 관대 |

`rbo`는 쌍마다 선형 시간이 들어 전 쌍에 못 돌린다. **tfidf 상위 100건을
재순위하는 용도**로만 쓴다.

#### (역사) 점수 척도가 서로 달랐다

같은 데이터(선케어 147건)에서 나온 분포다.

| method | 평균 | 중앙값 |
|---|---|---|
| tfidf | 0.157 | 0.134 |
| jaccard | 0.258 | 0.248 |
| rbo | 0.459 | 0.478 |

**tfidf의 0.5와 rbo의 0.5는 같은 뜻이 아니다.** 화면에서 백분율로 바꿔 보여줄
때는 method를 함께 봐야 한다. 그래서 API 응답이 `method`를 돌려준다.

#### (역사) 결과가 갈렸는가

상위 10개 중 평균 몇 개가 겹치는지 측정했다.

| 비교 | 겹침 |
|---|---|
| jaccard ↔ tfidf | 6.13개 (61%) |
| jaccard ↔ rbo | 4.56개 (46%) |
| rbo ↔ tfidf | 3.71개 (37%) |

**세 방식이 실제로 다른 답을 낸다.** 특히 tfidf와 rbo는 상위 10개 중 4개도
겹치지 않는다 — 나란히 두고 비교할 가치가 있다는 뜻이다.

## 카테고리 안에서만 비교한다

선케어의 대체품이 클렌징이면 안 된다. 성분만 보면 둘 다 정제수·글리세린이
앞자리라 꽤 비슷하게 나오지만 쓰임이 다르다.

**IDF도 카테고리 안에서 계산한다.** 선케어에서는 자외선차단제 성분이 흔해
변별력이 낮게 잡히는 게 맞고, 그래야 같은 유기자차끼리도 미세한 차이가
드러난다. 전체 카탈로그로 IDF를 잡으면 "선케어냐 아니냐"만 보게 된다.

  0.338  에스트라 더마UV365 무기자차 선크림
         공통: 사이클로헥사실록세인, 폴리글리세릴-2다이폴리하이드록시…  ← 무기자차 분산제

기준  식물나라 선 스틱
  0.441  식물나라 워터프루프 선 스틱

**근거 성분에 정제수·글리세린이 하나도 없다.** IDF가 의도대로 일하고 있다는
가장 직접적인 증거다. `shared_ingredients`는 IDF 큰 순으로 5개를 담는다 —
흔한 성분을 근거라고 보여주면 사용자가 추천을 신뢰하지 않는다.

## 중복 제품 탐지 (부산물)

유사도 1.0 쌍은 **같은 제품이 두 번 들어간 것**이다. 선케어에서 7쌍이 나왔고
전부 실제 중복이었다 — 기획/단품, 용량만 다른 변형.

```
1.0000  [1549] 코스알엑스 울트라 라이트 물막 수분 선세럼 50ml 더블기획
        [1593] 코스알엑스 울트라 라이트 인비저블 선세럼 50ml 기획 (+15ml)
1.0000  [919]  아비브 글루타치온좀 CC 선크림 토닝 튜브 50ml 더블 기획
        [1555] 아비브 글루타치온좀 CC 선크림 토닝 튜브 50ml
```

`--duplicates`로 뽑는다. DB 정리 작업의 입력으로 쓰라고 넣은 기능이다.

## 실행

```bash
python scripts/compute_similarities.py                      # 전체 (카테고리별로 순회)
python scripts/compute_similarities.py --category 선케어
python scripts/compute_similarities.py --dry-run            # 적재 없이 통계만
python scripts/compute_similarities.py --duplicates         # 중복 후보 목록
```

멱등하다. 처리한 (제품 × 방식) 범위를 지우고 다시 넣으므로 여러 번 돌려도
행수가 늘지 않는다.

그래도 재실행이 싸다 — 제품 데이터가 바뀌면 그냥 다시 돌리면 된다.

## 조회 API

```
GET /api/v1/products/{id}/similar?method=tfidf&limit=10
```

```json
{
  "seedId": 890,
  "method": "tfidf",
  "items": [
    { "id": 891, "name": "…", "brand": "라운드랩", "category": "선케어",
      "price": 24500, "imageUrl": "…", "rating": 4.8, "reviewCount": 22850,
      "score": 0.5559, "sharedIngredients": ["디에칠헥실부타미도트리아존", "…"] }
  ]

```

- `method` 기본값 `tfidf`, 잘못된 값은 422
- `limit` 최대 20 — 배치가 제품당 20개만 적재하므로 더 줄 게 없다
- **유사도가 아직 없으면 빈 배열에 200.** 404가 아니다 — 제품은 존재하고
  계산이 안 됐을 뿐이며, 프론트는 그때 '준비 중' 자리표시자를 그대로 둔다
- 캐싱은 붙이지 않았다. 부분 적재 상태에서 배치와 무효화 시점을 맞추는 게
  이르다. 조회는 `idx_similarities_lookup` 하나로 끝난다

## 계산 대상은 단일제품뿐이다

> 2026-09-10. 아래 §1이 이 작업으로 해소됐다.

`products.composition`이 제품 구성을 네 값으로 나눈다(건수는 2026-09-10 실측, 현재 값은 [db-schema.md](db-schema.md)). 배치는 `single`만 계산하고
조회 API도 기본으로 `single`만 내보낸다. 판정 규칙은
[`backend/app/utils/composition.py`](../backend/app/utils/composition.py).

| 값 | 건수 | 설명 |
|---|---:|---|
| `single` | 2,489 | 순수 단일제품 — 계산 대상 |
| `bonus` | 1,090 | 본품 증량·화장품 증정 (`+50ml`, `1+1`) |
| `bundle` | 357 | 묶음·N종·세트·키트 |
| `goods` | 81 | 비화장품 굿즈 동봉 (키링·파우치·브러쉬) |

카테고리별 잔여율은 스킨케어 61.1% · 마스크팩 63.3% · 클렌징 65.9%인데
**선케어만 41.4%(145 → 60건)** 다. 후보가 적어 대체품 품질이 가장 먼저 나빠질 자리다.
`bonus`를 다시 포함할지는 결과를 보고 정한다 — `CompositionFilter` 기본값과 배치
쿼리의 `composition = 'single'` 두 곳만 바꾸면 된다.

### 왜 bonus까지 빼는가

`bonus`는 대부분 깨끗하다. 고유 성분 100개 초과 비율이 단일제품 0.9%, bonus 3.5%로
묶음(19~29%)과는 자릿수가 다르다. 다만 **다른 제품을 얹었는데 이름만으로는 구별되지
않는 경우**가 1,537건 중 39건 섞여 있다.

```
헤브블루 살몬 PDRN 센텔라 토너 200ml 기획 (+연어 크림 20ml)
  → 성분 57개, 정제수 2회 — 두 제품의 전성분이 이어 붙었다
```

`+크림 9ml 증정`인데 정제수가 1회뿐인 건도 많다. 판매자가 본품 전성분만 적어둔
것이라, **이름으로는 오염 여부를 판별할 수 없다.** 1차 검증에서는 안전한 쪽을
택했다.

### 2. 파싱 잔해가 점수를 체계적으로 누른다 (일부 해소)

> 2026-09-10 파서를 보강했다. 아래 수치는 그 뒤 기준이다.

'의심 성분'은 **협회 사전에 없고 DF=1인 성분**이다. 단일제품에 쓰인 3,717종 중
**336종**이 여기 해당한다(보강 전 780종). `scripts/report_parse_residue.py`가
언제든 다시 센다.

**보강으로 잡은 것**

| 유형 | 예 |
|---|---|
| 구간 라벨 → 구분자 | `아시아틱애씨드 [STEP3] 정제수` → 두 성분 |
| 함량 앞의 마커 | `마그네슘설페이트*(4.75 ppb)` |
| `%/ppm` 외 단위 | `비타민C(1.5g)` · `(4.75 ppb)` |
| 각주 번호 | `부틸렌글라이콜3)4)5)` · `마이카³` · `아시아티코사이드#` |
| 선두 표시 | `① 캐모마일꽃수` · `*살리실릭애씨드` · `■ 정제수` · `'정제수` |
| 안내문구 | `페녹시에탄올 [iln44077]* 제공된 성분은` |
| 띄어 쓴 숫자 쉼표 | `1, 2-헥산다이올`이 `1` + `2-헥산다이올`로 쪼개지던 것 |
| `*` 뒤 각주 설명 | `콜라겐추출물 *분사제 : 이산화탄소` → `콜라겐추출물` |
| `STEP NN` 구간 라벨 | `리날룰 STEP 02 : … 마스크 정제수` → `리날룰` 회수 |
| 표기 문구 | `합성 향료 및 알러젠 (최종 공정 무첨가)` → 통째로 버림 |
| 다른 구분자 | 전각 쉼표 `，` · 콜론 `세럼: 정제수` · 한글 사이 마침표 |
| 괄호 밖 함량 | `판테놀 5%` · `에델바이스꽃/잎추출물 100,000ppm` |
| 성분 아닌 토큰 | `E65R` · `TONIC` · `1,2`(한글 없음) · `앰플`·`에센스`(제형 라벨) |
| 전각 문자 | `바쿠치올(100ppm）` — 한쪽만 전각이라 함량 제거가 어긋났다 |
| 각주 기호 설명 | `토타네올™ ++표시` · `(밀크 콜라겐™ 성분 *표기) 정제수` |

**안내문구는 원문 단계에서 자른다.** 토큰별로 지우면 늦다 — 쉼표 없이 공백으로
구분하는 제품(바비브라운 계열)은 vocab 분리를 타면서 문장이 단어별로 쪼개져
`경우에`·`따라`·`변경될`·`수`가 각각 성분이 됐다(각 DF=3).

각주 설명이 성분 **앞**에 오는 경우도 있다. `(밀크 콜라겐™ 성분 *표기) 정제수`를
뒤에서 자르면 정작 `정제수`가 날아간다 — 괄호 안에 `표기`·`표시`가 있을 때만
선두 라벨로 보고 걷어낸다.

**표기 문구는 성분이 아니라 문장이다.** 에스티로더 계열(크리니크·랩시리즈·
바비브라운·MAC·달팡)과 바이오더마가 전성분 뒤에 같은 안내 문구를 붙이는데,
그게 쉼표로 쪼개져 `있습니다.` · `참고하시거나` · `부탁` 같은 조각으로 등록돼
있었다. 협회 사전 21,910종에 `습니다`·`무첨가`·`참고`가 든 성분은 하나도 없어
안전하게 버린다. 다만 **문구 앞에 실제 성분이 붙어 있으면 그것만 남긴다** —
`페녹시에탄올 제공된 성분은 …` → `페녹시에탄올`.

마지막 항목이 DF가 가장 높았다. `1`(DF=12)·`2-헥산다이올`(DF=11)·`'정제수`(DF=8)·
`■`(DF=7)가 가짜 성분으로 등록돼 있었고 지금은 전부 사라졌다.

**쉼표 판정은 공백 유무로 나뉜다.** 붙여 쓴 경우는 앞뒤 글자가 숫자면 성분명
내부로 보고(`비스-…헥산1,4-다이카복실레이트`), 띄어 쓴 경우는 모은 것이 전부
숫자일 때만 내부로 본다(`1, 2-헥산다이올`은 내부지만 `피이지-90, 1,2-헥산다이올`은
구분자다). 한쪽 규칙만 쓰면 반드시 다른 쪽이 깨진다 — 실제로 두 번 겪었다.

**남은 것의 성격이 다르다.** 최다 유형이 파싱 실패가 아니라 **판매자가 잘못
적은 오타**(`프로판다이을`←올, `크프릭트라이글리세라이드`←카프릴릭)다. 규칙으로는
못 고친다.

### 오타는 pg_trgm으로 교정한다

`scripts/find_typo_aliases.py`가 협회 표준명 21,910종에 최근접 매칭을 돌려
후보를 뽑고, `data/seed/ingredient_typo_fixes.csv`에 낸다.
`seed_ingredients.py`가 `verdict = ok`인 것만 별칭으로 적재한다.

CSV를 시드 입력으로 두는 이유는 **재시드해도 살아남기** 위해서다.
`ingredient_aliases`에 직접 넣으면 시드의 upsert가 `ingredient_id`를
덮어써 사라진다.

**유사도만으로는 오타와 다른 성분을 구별할 수 없다.** 0.88짜리
`소듐아크릴레이트크로스폴리머 → …크로스폴리머-2`는 서로 다른 성분이다.
편집 형태를 함께 본다.

| 판정 | 종수 | 근거 |
|---|---:|---|
| 자동 `ok` | 70 | 1~2글자 차이 — `…하이알루네이트` → `…하이알루로네이트` |
| 자동 `ok` | 42 | 표준명에 잔해가 붙음 — `6-다이소듐이디티에이` · `…콜라겐+표시` |
| 수기 `ok` | 20 | 자동 판정이 보수적이라 놓친 것 |
| 수기 `no` | 15 | 실제로 다른 성분 |

자동 판정이 남긴 35종은 사람이 실물을 보고 채웠다. 대부분 명백한 오타였다.

```
소듐시트레이      → 소듐시트레이트        (트 잘림)
적색504          → 적색504호            (호 잘림)
듐하이알루로네이트…  → 소듐하이알루로네이트…   (소 빠짐)
ad5모늄…         → 암모늄…              (인코딩 깨짐)
쿠티박테리움그라눌로… → …그라눌로숨…         (숨 빠짐)
```

반면 `no`로 막은 것들은 유사도가 높아도 서로 다른 성분이다.

```
라즈베리씨오일/팜오일…   → 아마씨오일/팜오일…      다른 원료
글리세릴모노스테아레이트  → 글리세릴스테아레이트     '모노' 유무
락토바실러스/석류추출물   → …석류발효추출물         '발효' 유무
소듐아크릴레이트크로스폴리머 → …크로스폴리머-2       변형 번호
```

**의심 성분을 가진 제품을 지우는 방안도 검토했지만 접었다.** 41건(1.7%)이
대상인데, 그중 상당수가 위처럼 고칠 수 있는 오타 하나 때문에 걸린 정상
제품이었다. 지우는 대신 교정하는 편이 낫다.

**LLM보다 이쪽이 나은 이유**는 후보가 반드시 실재하는 성분이기 때문이다.
LLM은 사전을 모르는 채 추측해 없는 성분명을 지어낼 수 있고, 성분 사전은
유사도의 근간이라 그게 들어가면 조용히 결과가 틀어진다.

제품 단위 영향 (유사도 계산 대상 2,461건 기준).

| 기준 | 제품 | 비율 |
|---|---:|---:|
| 의심 성분 1개 이상 | 182 | 7.4% |
| 3개 이상 | 29 | 1.2% |
| 벡터의 10% 이상 | 17 | 0.7% |

제품 단위 제거는 하지 않았다 — 대부분 성분 하나만 이상한 정상 제품이다.

**영향**: 코사인은 `<a,b> / (|a|·|b|)`인데, DF=1 성분은 어떤 쌍의 공통 성분도 될 수
없어 **분자에는 기여하지 않고 분모만 키운다.** 게다가 희귀해서 IDF가 최대치로 붙는다.

```
의심 성분 보유 제품 비율 (파서 보강 전 → 후)
  스킨케어  15.3% →  7.1%    마스크팩  15.2% →  8.6%
  클렌징    11.9% →  6.8%    선케어    29.0% →  8.3%
```

기준 제품 자기 목록의 순위는 안 흔들린다(`|a|`가 상수라 전체가 같은 비율로 눌린다).
문제는 **`|b|`가 부푼 제품이 남의 추천 목록에서 부당하게 밀린다**는 것이다.
전성분 표기가 지저분하다는 이유로 대체품이 될 기회를 잃는다.

### 논의할 선택지

| | 무엇 | 대가 |
|---|---|---|
| 근본 | 묶음 제품 분리 + 전성분 파서 보강 | 팀원1 작업 범위. 대괄호 787종이 원천 소멸 |
| ~~필터 확대~~ | ~~이름의 `N종`/`택1`/`모음`을 묶음 신호에 추가~~ | **completed** — `composition`으로 흡수됐다 |
| 계산 완화 | DF=1 성분을 벡터에서 제외 | 분자는 안 바뀌고 분모만 정직해진다. 다만 진짜 희귀 성분도 함께 버린다 |

**배치의 삭제 범위 문제는 아직 남아 있다.** `write()`는 계산 대상 제품만
`DELETE` 하므로, 필터를 좁혀 재실행하면 새로 제외된 제품의 예전 행이 남는다.
`similar_id` 쪽은 아예 정리되지 않는다. composition 도입 때는 아래 쿼리로
일회성 정리를 했지만, 규칙을 다시 손대면 또 필요하다.

```sql
DELETE FROM similarities s USING products p
 WHERE p.id IN (s.product_id, s.similar_id) AND p.composition <> 'single';
```

  사람(성분 전문가) 표본 검수로 일치율을 재야 nDCG 0.799를 "독립 검증"으로 말할 수 있다
- **bonus 재포함 판단** — 배치는 아직 `single`만 계산한다. 선케어는 후보가 적어 대체품이 빈약할 수 있다
- 방식 선정(hybrid), 프론트 연결(`/alternatives`·홈 대체품·상세), 가격·피부 궁합 축(`priceDelta`·`skinMatch`)은 **끝났다**

## 피부 궁합 (`services/skin_fit.py`)

성분 기능 라벨(`ingredient_functions`)로 "이 제품이 내 피부에 맞는가"를 판정한다. **이 판정이 화면 전체의 정본**이다 —
궁합 카드·목록 배지·대체품 `skinMatch`·전성분 칩·피부타입 필터·`sort=skinFit`·홈 추천·예산 가이드가 모두 같은 계산을 쓴다.

    계산     services/skin_fit.evaluate  →  scripts/compute_skin_fit.py  →  product_skin_fit(제품 × 8타입)
    카드     GET /api/v1/products/{id}/skin-fit?skinType=samak     # 판정 + 이유(성분 위치 포함), 실시간 evaluate
    배지     GET /api/v1/skin-fit?ids=1,2,3&skinType=samak          # product_skin_fit 조회, 최대 60개
    대체품   GET /api/v1/products/{id}/similar?fitFor=samak          # 항목마다 skinMatch(걸러내지 않음)
    상세     GET /api/v1/products/{id}?skinType=samak                # 전성분 grade(key|warn|normal|null)를 이 타입 기준으로
    필터     GET /api/v1/products?skinType=samak                     # product_skin_fit.excluded 제품을 뺌
    정렬     sort=skinFit                                            # product_skin_fit.score

- **선호 기능**: 타입마다 가중이 다르다(유리구슬=진정·장벽, 수부지=보습, 화산=피지·진정, 메밀묵=미백 …). 활성·에몰리언트 성분이
  그 기능을 앞 성분일수록 많이 가질수록 가점. 타입별 기준 규모(`REF`)로 포화시켜 타입마다 분포가 비슷하다.
- **기피 플래그**(I 자극 · F 향료 · L 건조 알코올): **확신도 3**(또는 고시 목록)만 근거로 쓴다. 추정에 근거한 "주의"는 사용자에게 해롭다.
- **하드 제외**(목록에서 뺌): 식약처 알레르기 유발 착향제 고시 목록 성분 또는 일반 '향료'/'조합향료'(화산·유리구슬),
  건조 알코올 확신도 3(수부지·사막·유리구슬). 그 밖의 향료·자극 의심은 감점과 "주의" 표시만 하고 빼지 않는다.
  전환 전(태그 기반)과 비교: 향료 제외 대상은 단일제품 기준 1,040개로 **정확히 같고**, 알코올은 265 → 272(아이소프로필알코올 +7).
- **판정**: good ≥ 66 · caution(플래그 하나의 감점 ≥ 12 / 합 ≥ 18 / 점수 < 28) · 그 밖에 ok.
  활성·에몰리언트 근거가 3종 미만이면 `unknown`(모르는 것을 "무난"으로 보여 주지 않는다).
- **전성분 칩**(`classify_ingredient`): warn = 고시 목록·일반 향료·건조 알코올(타입 무관) 또는 내 타입이 기피하는 플래그(확신도 3),
  key = 내 타입의 선호 기능을 가진 활성·에몰리언트(확신도 2+). 진단 전에는 key 없이 warn만 보인다.
  카드의 이유를 누르면 그 이유를 만든 성분의 칩이 강조된다(`FitReason.ingredients`의 position).
- **진단 5축 보정은 쓰지 않는다.** 목록 정렬·배지·카드가 같은 값을 보게 하려는 것이다(서비스에는 `axes` 인자가 남아 있다).
- 한계: 타입별 가중은 `criteria.csv`의 케어 목적과 일반적인 성분 지식에 근거한 것이고 임상 검증이 아니다.
  식약처 목록은 저장소의 기존 파일(`exclusion_criteria.csv`)을 옮긴 것이라 고시 원문과 대조하지 못했다.
  의학적 판단이 아니라 성분 구성 기준의 참고 정보로만 보여 준다.
- 정렬(`sort=skinFit`) 상위 20개는 전환 전과 2~9개만 겹친다(태그 붙은 성분 수 → 가중 점수로 기준이 바뀌었다).


## 성분 분석 (`services/product_analysis.py`, 화면 `/analysis/:id`)

**어느 제품이든** 제품 상세의 "이 제품 성분 분석 보기"와 화장대의 보유 제품에서 열리는 성분 리포트. 제품 상세가 상품 정보(가격·리뷰·구매)라면 이 화면은 **해석**이다. (예전 주소 `/closet/:id/analysis`는 `/analysis/:id`로 넘어간다. 화장대에 없는 제품이면 화장대 구역 제목이 "내 화장대와 견주면"으로 바뀐다.)

    GET /api/v1/products/{id}/analysis?skinType=samak&closetIds=12,34,56&moisture=3&oil=7&sensitivity=8&pigmentation=4&trouble=6

| 구역 | 내용 | 근거 |
|---|---|---|
| 요약 | 제품·궁합 판정·점수·이유 | `skin_fit.evaluate`(카드와 같은 값) |
| 내 피부 상태와 견주면 | 진단 5축(수분·유분·민감도·색소·트러블, 문답+얼굴 사진 분석)마다 신경 쓸 정도와 이 제품이 돕는 정도, 자극 우려, 한 줄 요약 | 축 → 돕는 기능(수분=보습·장벽, 유분=피지, 민감도=진정·장벽, 색소=미백·항산화, 트러블=피지·진정)의 강도 |
| 핵심 성분 | 앞쪽 활성 성분 5개와 기능, 내 피부 추천 표시 | 라벨(활성·확신도 2+) |
| 이 제품이 하는 일 | 기능 9종 강도 막대(0~100), ★ = 내 타입이 중요하게 보는 기능 | 활성·에몰리언트 성분의 위치 가중 합 |
| 주의 성분 | 고시 목록·향료·알코올·자극을 성분 이름과 함께, 성분 하나는 한 종류에만 | 고시 목록·확신도 3 플래그 |
| 전성분 해부도 | 함량 순서의 띠, 기능별 색, 주의 성분 표시 | 전 성분(라벨 없는 성분 포함) |
| 내 화장대에서의 위치 | 겹치는 기능, 아직 부족한 기능(피부타입을 알 때), **성분이 비슷한 내 제품** | 같은 카테고리의 보유 제품과 기능 강도 비교. 비슷한 정도는 **상세·대체품·홈과 같은 hybrid 유사도**(`similarities`)를 그대로 쓴다(상위 20개 안의 쌍만) |

- 기능 강도 = 1 − exp(−Σ 위치 가중 / 2.0). 활성 성분 하나가 맨 앞이면 ≈ 39, 셋이면 ≈ 78. 50 이상이면 "강하다"(겹침 기준), 40 미만이면 "약하다"(부족 기준).
- `closetIds`는 화장대 제품 id들(최대 100). 서버는 같은 카테고리만 쓰고 자기 자신은 무시한다. 응답은 사용자마다 달라 캐시하지 않는다.
- 진단 전에는 궁합·추천 표시·부족한 기능을 숨기고 성분 분석(핵심 성분·기능·주의·해부도)만 보여 준다.
- 화장대에서 삭제한 제품은 화장대에서 누르면 계속 제품 상세로 간다.
- **내 피부 상태 비교**는 진단 5축이 **다섯 개 모두** 있을 때만 계산한다. 축의 방향은 수분만 높을수록 좋고(신경 쓸 정도 = 10 − 점수),
  나머지는 높을수록 신경 쓸 부분이다(6 이상 = 신경 쓸 부분, 4~5 = 약간). 이 비교는 궁합 점수를 바꾸지 않는다.
- **내 피부 상태의 출처는 하나만 쓴다**(`hooks/useSkinStateSource.ts`): AI 사진 분석이 있으면 **항상 그것**, 없으면 문답 진단, 둘 다 없으면 촬영 안내.
  화면에 "AI 사진 분석 기준 · 10/21 · 8개 항목"처럼 출처·날짜·항목 수를 적는다.
  **막지는 않는다** — 제품 분석(핵심 성분·기능·주의 성분·해부도·화장대 위치)은 사진 없이 본다. 촬영·동의는 `FacePhotoScreen`이 처리한다
  (처음 한 번만 동의, 철회는 마이페이지). 저장된 분석 결과를 다시 읽는 데는 외부 비용이 들지 않는다(원본 사진은 저장하지 않고 결과만 저장).
- **사진 분석이 출처면 분석된 항목 전부를 견준다**(무료 8개: 유분·수분·홍조·잡티·트러블·모공·주름 + 피부 분류 / 구독 16개: + 탄력·광채·피부결·다크서클·눈밑 불룩·눈꺼풀 처짐 2개·눈밑 꺼짐).
  `GET .../analysis?concerns=oiliness:79,moisture:74,…` (점수 0~100, **높을수록 좋음**). 항목 → 돕는 기능: 유분=피지, 수분=보습·장벽, 홍조=진정·장벽, 잡티=미백·항산화,
  트러블=피지·진정, 모공=피지·각질, 주름=주름·항산화, 탄력=주름·탄력, 광채=미백·항산화·보습, 피부결=각질·보습, 다크서클=미백·주름(대략적).
  눈밑 불룩·눈꺼풀 처짐·눈밑 꺼짐은 화장품 성분으로 바뀌기 어려운 구조적 항목이라 견주지 않고 "참고용"으로만 보여 준다.
  신경 쓸 정도: 70점 미만 = 신경 쓸 부분, 70~79 = 약간, 80 이상 = 좋은 편. 무료 사용자에게는 구독하면 더 견줄 수 있는 항목이 있다는 안내가 붙는다.
- 문답 진단만 있을 때는 5축으로 견주고(진단 5축은 수분만 높을수록 좋고 나머지는 높을수록 신경 쓸 부분), 사진 분석을 권하는 한 줄이 붙는다.
