## 왜 IDF가 필요한가

전성분에서 **상위 6종이 사실상 모든 제품에 들어 있다.**

| 성분 | 출현율 |
|---|---|
| 글리세린 | 85% |
| 정제수 | 84% |
| 1,2-헥산다이올 | 81% |
| 부틸렌글라이콜 | 80% |
| 에틸헥실글리세린 | 66% |
| 소듐하이알루로네이트 | 51% |

단순 교집합으로 세면 아무 두 제품이나 이 여섯 개가 겹쳐서 비슷해 보인다.
**IDF는 이 성분들의 가중치를 0에 가깝게 만들어 계산에서 사실상 지운다.**
그러면 판테놀·마데카소사이드·디에칠헥실부타미도트리아존처럼 실제로 제형을
가르는 성분만 점수를 결정한다.

`backend/tests/test_similarity.py::test_common_ingredients_score_low`가 이
경계를 지킨다. 이 테스트가 깨지면 추천이 정제수를 근거로 아무거나 고르게 된다.

성분 문서빈도 분포 — 실제 제품에 붙은 성분은 사전 25,923종 중 **6,403종**이다.

| DF | 성분 수 |
|---|---|
| 1건 | 2,818 |
| 2–5 | 1,591 |
| 6–20 | 994 |
| 21–100 | 664 |
| 101–500 | 279 |
| 501–2,000 | 51 |
| 2,000+ | 6 |

## 세 가지 방식

`similarities`의 PK가 `(product_id, similar_id, method)`라 세 결과를 나란히
적재해 비교할 수 있다. **정답 데이터가 없으므로 눈으로 보고 정한다.**

| method | 무엇을 보나 | 성격 |
|---|---|---|
| `tfidf` | IDF 가중 코사인 | **기본값.** 흔한 성분을 죽인다. 가장 엄격 |
| `jaccard` | 단순 교집합 / 합집합 | 기준선. IDF가 무슨 일을 하는지 보여주는 대조군 |
| `rbo` | 표기 순서까지 (p=0.9) | 함량 순서를 반영. 가장 관대 |

`rbo`는 쌍마다 선형 시간이 들어 전 쌍에 못 돌린다. **tfidf 상위 100건을
재순위하는 용도**로만 쓴다.

### 점수 척도가 서로 다르다

같은 데이터(선케어 147건)에서 나온 분포다.

| method | 평균 | 중앙값 |
|---|---|---|
| tfidf | 0.157 | 0.134 |
| jaccard | 0.258 | 0.248 |
| rbo | 0.459 | 0.478 |

**tfidf의 0.5와 rbo의 0.5는 같은 뜻이 아니다.** 화면에서 백분율로 바꿔 보여줄
때는 method를 함께 봐야 한다. 그래서 API 응답이 `method`를 돌려준다.

### 실제로 결과가 갈리는가

상위 10개 중 평균 몇 개가 겹치는지 측정했다.

| 비교 | 겹침 |
|---|---|
| jaccard ↔ tfidf | 6.13개 (61%) |
| jaccard ↔ rbo | 4.56개 (46%) |
| rbo ↔ tfidf | 3.71개 (37%) |

**세 방식이 실제로 다른 답을 낸다.** 특히 tfidf와 rbo는 상위 10개 중 4개도
겹치지 않는다 — 나란히 두고 비교할 가치가 있다는 뜻이다.

| 규칙 | 건수 | 이유 |
|---|---|---|
| `composition <> 'single'` | 1,595 | 전성분이 제품 하나에 대응한다고 보장할 수 없다 — 위 절 참고 |
| 묶음 (`ingredient_count_raw > 고유수 × 2`) | 8 | 위 필터를 통과한 뒤 비율로 걸리는 잔여분 |
| 성분 5개 미만 | 30 | 벡터가 짧아 흔한 성분 몇 개로 점수가 1.0 가까이 튄다 |

## 카테고리 안에서만 비교한다

선케어의 대체품이 클렌징이면 안 된다. 성분만 보면 둘 다 정제수·글리세린이
앞자리라 꽤 비슷하게 나오지만 쓰임이 다르다.

**IDF도 카테고리 안에서 계산한다.** 선케어에서는 자외선차단제 성분이 흔해
변별력이 낮게 잡히는 게 맞고, 그래야 같은 유기자차끼리도 미세한 차이가
드러난다. 전체 카탈로그로 IDF를 잡으면 "선케어냐 아니냐"만 보게 된다.

## 조회 API

```
GET /api/v1/products/{id}/similar?method=tfidf&limit=10
```

```json
{
  "seedId": 890,
  "method": "tfidf",
  "items": [
    { "id": 891, "name": "…", "brand": "라운드랩", "category": "선케어",
      "price": 24500, "imageUrl": "…", "rating": 4.8, "reviewCount": 22850,
      "score": 0.5559, "sharedIngredients": ["디에칠헥실부타미도트리아존", "…"] }
  ]
}
```

- `method` 기본값 `tfidf`, 잘못된 값은 422
- `limit` 최대 20 — 배치가 제품당 20개만 적재하므로 더 줄 게 없다
- **유사도가 아직 없으면 빈 배열에 200.** 404가 아니다 — 제품은 존재하고
  계산이 안 됐을 뿐이며, 프론트는 그때 '준비 중' 자리표시자를 그대로 둔다
- 캐싱은 붙이지 않았다. 부분 적재 상태에서 배치와 무효화 시점을 맞추는 게
  이르다. 조회는 `idx_similarities_lookup` 하나로 끝난다

## 계산 대상은 단일제품뿐이다

> 2026-09-10. 아래 §1이 이 작업으로 해소됐다.

`products.composition`이 제품 구성을 네 값으로 나눈다. 배치는 `single`만 계산하고
조회 API도 기본으로 `single`만 내보낸다. 판정 규칙은
[`backend/app/utils/composition.py`](../backend/app/utils/composition.py).

| 값 | 건수 | 설명 |
|---|---:|---|
| `single` | 2,549 | 순수 단일제품 — 계산 대상 |
| `bonus` | 1,137 | 본품 증량·화장품 증정 (`+50ml`, `1+1`) |
| `bundle` | 372 | 묶음·N종·세트·키트 |
| `goods` | 86 | 비화장품 굿즈 동봉 (키링·파우치·브러쉬) |

카테고리별 잔여율은 스킨케어 60.6% · 마스크팩 63.3% · 클렌징 65.4%인데
**선케어만 42.3%(163 → 69건)** 다. 후보가 적어 대체품 품질이 가장 먼저 나빠질 자리다.
`bonus`를 다시 포함할지는 결과를 보고 정한다 — `CompositionFilter` 기본값과 배치
쿼리의 `composition = 'single'` 두 곳만 바꾸면 된다.

### 왜 bonus까지 빼는가

`bonus`는 대부분 깨끗하다. 고유 성분 100개 초과 비율이 단일제품 0.9%, bonus 3.5%로
묶음(19~29%)과는 자릿수가 다르다. 다만 **다른 제품을 얹었는데 이름만으로는 구별되지
않는 경우**가 1,537건 중 39건 섞여 있다.

```
헤브블루 살몬 PDRN 센텔라 토너 200ml 기획 (+연어 크림 20ml)
  → 성분 57개, 정제수 2회 — 두 제품의 전성분이 이어 붙었다
```

`+크림 9ml 증정`인데 정제수가 1회뿐인 건도 많다. 판매자가 본품 전성분만 적어둔
것이라, **이름으로는 오염 여부를 판별할 수 없다.** 1차 검증에서는 안전한 쪽을
택했다.

## 알려진 문제 — 팀 논의 필요

> 2026-08-30 조사. §1은 위 작업으로 해소됐고, §2는 **아직 고치지 않았다.**

### 1. ~~묶음 제품 필터가 대부분을 놓친다~~ (해소)

비율 규칙 `ingredient_count_raw > 고유 성분수 × 2`는 68건만 잡았다. **서로 다른
제품을 묶으면 성분이 겹치지 않아 비율이 오르지 않기** 때문이다.

| 제품 | raw / 고유 | 배수 |
|---|---|---|
| 스킨푸드 패드 레시피 11종 모음 | 392 / 196 | 2.00 |
| 아누아 데일리케어 마스크팩 8종 | 361 / 197 | 1.83 |
| 아로셀 하이드로겔 마스크 3종 택1 | 251 / 186 | 1.35 |

v5 정제본(PR #37)의 `처리메모`가 묶음 여부를 **명시**하면서 추측이 필요 없어졌다.
이름 규칙(`N종`·`택1`·`골라담기`·`세트`)이 나머지를 받는다. 비율 규칙은 보조로
남겨 뒀는데, composition 필터를 통과한 뒤 걸리는 건 4종 합쳐 8건뿐이다.

### 2. 파싱 잔해가 점수를 체계적으로 누른다

한 제품에만 등장하는 성분(DF=1)이 2,818종인데, 그중 **2,164종(77%)이 협회 사전에
없다.** 유형별로 보면 대부분 파싱 실패 조각이다.

| 유형 | 종수 | 예 |
|---|---|---|
| 대괄호 라벨이 성분명에 들러붙음 | 787 | `[콜라겐 세럼] 정제수` |
| 공백 구분인데 안 쪼개짐 | 736 | `소듐아세틸레이티드하이알루로네이트 롬앤 더 쥬시 래스팅 틴트 29 조선 무화과 정제수` |
| 괄호 짝 불일치 | 110 | `아이소류신5)` |
| 따옴표 잔류 | 34 | `크랜베리추출물"` |
| 그 외 (진짜 희귀 성분 포함) | 473 | `토코페볼(22.65PPM)` ← 판매자 오타 |

**영향**: 코사인은 `<a,b> / (|a|·|b|)`인데, DF=1 성분은 어떤 쌍의 공통 성분도 될 수
없어 **분자에는 기여하지 않고 분모만 키운다.** 게다가 희귀해서 IDF가 최대치로 붙는다.

```
선케어 기준 · 제품 벡터 길이에서 DF=1 성분이 차지하는 비중
  중앙값 23.2%   최대 87.3%
  절반 이상이 DF=1인 제품: 13건 / 167건
```

기준 제품 자기 목록의 순위는 안 흔들린다(`|a|`가 상수라 전체가 같은 비율로 눌린다).
문제는 **`|b|`가 부푼 제품이 남의 추천 목록에서 부당하게 밀린다**는 것이다.
전성분 표기가 지저분하다는 이유로 대체품이 될 기회를 잃는다.

### 논의할 선택지

| | 무엇 | 대가 |
|---|---|---|
| 근본 | 묶음 제품 분리 + 전성분 파서 보강 | 팀원1 작업 범위. 대괄호 787종이 원천 소멸 |
| ~~필터 확대~~ | ~~이름의 `N종`/`택1`/`모음`을 묶음 신호에 추가~~ | **completed** — `composition`으로 흡수됐다 |
| 계산 완화 | DF=1 성분을 벡터에서 제외 | 분자는 안 바뀌고 분모만 정직해진다. 다만 진짜 희귀 성분도 함께 버린다 |

**배치의 삭제 범위 문제는 아직 남아 있다.** `write()`는 계산 대상 제품만
`DELETE` 하므로, 필터를 좁혀 재실행하면 새로 제외된 제품의 예전 행이 남는다.
`similar_id` 쪽은 아예 정리되지 않는다. composition 도입 때는 아래 쿼리로
일회성 정리를 했지만, 규칙을 다시 손대면 또 필요하다.

```sql
DELETE FROM similarities s USING products p
 WHERE p.id IN (s.product_id, s.similar_id) AND p.composition <> 'single';
```
