## 왜 IDF가 필요한가

전성분에서 **상위 6종이 사실상 모든 제품에 들어 있다.**

| 성분 | 출현율 |
|---|---|
| 글리세린 | 85% |
| 정제수 | 84% |
| 1,2-헥산다이올 | 81% |
| 부틸렌글라이콜 | 80% |
| 에틸헥실글리세린 | 66% |
| 소듐하이알루로네이트 | 51% |

단순 교집합으로 세면 아무 두 제품이나 이 여섯 개가 겹쳐서 비슷해 보인다.
**IDF는 이 성분들의 가중치를 0에 가깝게 만들어 계산에서 사실상 지운다.**
그러면 판테놀·마데카소사이드·디에칠헥실부타미도트리아존처럼 실제로 제형을
가르는 성분만 점수를 결정한다.

`backend/tests/test_similarity.py::test_common_ingredients_score_low`가 이
경계를 지킨다. 이 테스트가 깨지면 추천이 정제수를 근거로 아무거나 고르게 된다.

성분 문서빈도 분포 — 실제 제품에 붙은 성분은 사전 25,923종 중 **6,403종**이다.

| DF | 성분 수 |
|---|---|
| 1건 | 2,818 |
| 2–5 | 1,591 |
| 6–20 | 994 |
| 21–100 | 664 |
| 101–500 | 279 |
| 501–2,000 | 51 |
| 2,000+ | 6 |

## 세 가지 방식

`similarities`의 PK가 `(product_id, similar_id, method)`라 세 결과를 나란히
적재해 비교할 수 있다. **정답 데이터가 없으므로 눈으로 보고 정한다.**

| method | 무엇을 보나 | 성격 |
|---|---|---|
| `tfidf` | IDF 가중 코사인 | **기본값.** 흔한 성분을 죽인다. 가장 엄격 |
| `jaccard` | 단순 교집합 / 합집합 | 기준선. IDF가 무슨 일을 하는지 보여주는 대조군 |
| `rbo` | 표기 순서까지 (p=0.9) | 함량 순서를 반영. 가장 관대 |

`rbo`는 쌍마다 선형 시간이 들어 전 쌍에 못 돌린다. **tfidf 상위 100건을
재순위하는 용도**로만 쓴다.

### 점수 척도가 서로 다르다

같은 데이터(선케어 147건)에서 나온 분포다.

| method | 평균 | 중앙값 |
|---|---|---|
| tfidf | 0.157 | 0.134 |
| jaccard | 0.258 | 0.248 |
| rbo | 0.459 | 0.478 |

**tfidf의 0.5와 rbo의 0.5는 같은 뜻이 아니다.** 화면에서 백분율로 바꿔 보여줄
때는 method를 함께 봐야 한다. 그래서 API 응답이 `method`를 돌려준다.

### 실제로 결과가 갈리는가

상위 10개 중 평균 몇 개가 겹치는지 측정했다.

| 비교 | 겹침 |
|---|---|
| jaccard ↔ tfidf | 6.13개 (61%) |
| jaccard ↔ rbo | 4.56개 (46%) |
| rbo ↔ tfidf | 3.71개 (37%) |

**세 방식이 실제로 다른 답을 낸다.** 특히 tfidf와 rbo는 상위 10개 중 4개도
겹치지 않는다 — 나란히 두고 비교할 가치가 있다는 뜻이다.

## 계산에서 빼는 제품

| 규칙 | 건수 | 이유 |
|---|---|---|
| 묶음 (`ingredient_count_raw > 고유수 × 2`) | 68 | 'N종 택1'이 호수별 전성분을 이어 붙여, 어느 호수의 성분인지 알 수 없다 |
| 성분 5개 미만 | 42 | 벡터가 짧아 흔한 성분 몇 개로 점수가 1.0 가까이 튄다 |

4,150건 중 4,040건이 계산 대상이 된다.

## 카테고리 안에서만 비교한다

선케어의 대체품이 클렌징이면 안 된다. 성분만 보면 둘 다 정제수·글리세린이
앞자리라 꽤 비슷하게 나오지만 쓰임이 다르다.

**IDF도 카테고리 안에서 계산한다.** 선케어에서는 자외선차단제 성분이 흔해
변별력이 낮게 잡히는 게 맞고, 그래야 같은 유기자차끼리도 미세한 차이가
드러난다. 전체 카탈로그로 IDF를 잡으면 "선케어냐 아니냐"만 보게 된다.

**근거 성분에 정제수·글리세린이 하나도 없다.** IDF가 의도대로 일하고 있다는

흔한 성분을 근거라고 보여주면 사용자가 추천을 신뢰하지 않는다.

## 중복 제품 탐지 (부산물)

유사도 1.0 쌍은 **같은 제품이 두 번 들어간 것**이다. 선케어에서 7쌍이 나왔고
전부 실제 중복이었다 — 기획/단품, 용량만 다른 변형.

```
1.0000  [1549] 코스알엑스 울트라 라이트 물막 수분 선세럼 50ml 더블기획
        [1593] 코스알엑스 울트라 라이트 인비저블 선세럼 50ml 기획 (+15ml)
1.0000  [919]  아비브 글루타치온좀 CC 선크림 토닝 튜브 50ml 더블 기획
        [1555] 아비브 글루타치온좀 CC 선크림 토닝 튜브 50ml
```

`--duplicates`로 뽑는다. DB 정리 작업의 입력으로 쓰라고 넣은 기능이다.

## 실행

```bash
python scripts/compute_similarities.py                      # 전체 (카테고리별로 순회)
python scripts/compute_similarities.py --category 선케어
python scripts/compute_similarities.py --dry-run            # 적재 없이 통계만
python scripts/compute_similarities.py --duplicates         # 중복 후보 목록
```

멱등하다. 처리한 (제품 × 방식) 범위를 지우고 다시 넣으므로 여러 번 돌려도
행수가 늘지 않는다.

### 소요 시간

아래 표는 `--dry-run` 실측이다. **계산만 한 시간이고 적재는 빠져 있다.**

| 카테고리 | 제품 | 계산 행 | 계산 시간 |
|---|---|---|---|
| 스킨케어 | 2,087 | 41,740 × 3 | 19.9초 |
| 마스크팩 | 924 | 18,448 × 3 | 6.1초 |
| 클렌징 | 882 | 17,640 × 3 | 4.5초 |
| 선케어 | 147 | 2,940 × 3 | 2.1초 |
| **합계** | **4,040** | **242,304** | **32.6초** |

**쓰기가 계산보다 비싸다.** 같은 선케어를 두 번 돌린 실측이다.

| | 소계 |
|---|---|
| `--dry-run` (계산만) | 2.1초 |
| 실제 적재 (8,820행) | 6.1초 |

행당 쓰기 비용으로 외삽하면 전체 242,304행 적재는 **약 2분 반**이다
(계산 33초 + 쓰기 약 110초). Neon이 원격이라 대부분이 네트워크 왕복이다.

그래도 재실행이 싸다. 제품 데이터가 바뀌면 그냥 다시 돌리면 된다.

## 조회 API

```
GET /api/v1/products/{id}/similar?method=tfidf&limit=10
```

```json
{
  "seedId": 890,
  "method": "tfidf",
  "items": [
    { "id": 891, "name": "…", "brand": "라운드랩", "category": "선케어",
      "price": 24500, "imageUrl": "…", "rating": 4.8, "reviewCount": 22850,
      "score": 0.5559, "sharedIngredients": ["디에칠헥실부타미도트리아존", "…"] }
  ]
}
```

- `method` 기본값 `tfidf`, 잘못된 값은 422
- `limit` 최대 20 — 배치가 제품당 20개만 적재하므로 더 줄 게 없다
- **유사도가 아직 없으면 빈 배열에 200.** 404가 아니다 — 제품은 존재하고
  계산이 안 됐을 뿐이며, 프론트는 그때 '준비 중' 자리표시자를 그대로 둔다
- 캐싱은 붙이지 않았다. 부분 적재 상태에서 배치와 무효화 시점을 맞추는 게
  이르다. 조회는 `idx_similarities_lookup` 하나로 끝난다
