## 2. 기능별 지표와 합격선

### A. 유사도 (test: 신규 시드 40개)
- 지표: nDCG@10, P@5(등급 2), 1위 후보 대체 가능 비율
- 기준선: 같은 카테고리 무작위 / 평점순 / tfidf
- **합격**: hybrid 최종이 무작위·평점순보다 nDCG@10이 높고 쌍체 95% 구간이 0을 제외한다. tfidf 대비는 **차이를 있는 그대로 보고**(우위 여부를 합격 조건으로 두지 않는다)
- 보고: dev(기존 80 시드) 대비 test 하락폭 = 낙관 편향

### B. 궁합
- 입력 라벨: `review_sample.csv` 사람 검수 → 기능 라벨 정밀도(확신도별)
- 출력: 제품 40 × 타입 3 = 120건, 3등급(적합/보통/주의) 일치
- 지표: 정확도, 가중 kappa, **위험 방향 오류율**(사람 '주의' → 모델 '적합')
- **합격**: 위험 방향 오류율의 Wilson 상한 ≤ 10%, 가중 kappa 점추정 ≥ 0.40, 기준선(항상 '보통')보다 정확도 높음
- 불변식(전수): 하드 제외 성분 포함 제품이 '적합' 판정 **0건**

### C. 진단
- 정확도는 주장하지 않는다. 보고만 한다: 8타입 도달 여부, 무작위 응답 10만 건의 타입 분포·경계 비율, 문항별 민감도, 페르소나 30개 통과율
- **합격**: 8타입 모두 도달, 페르소나 통과율 ≥ 70%

### D. 추천·예산
- 불변식(무작위 요청 1,000건): 예산 초과·단계 순서 위반·제외 성분 위반 **0건**
- 품질: 같은 예산에서 평균 궁합 점수가 무작위 조합보다 높음(쌍체 구간이 0 제외)

### E. OCR — 앞면 사진만 (dev: item1~11, test: item12~48, 뒷면은 평가하지 않음)
- 지표: 정답 제품 top-1/top-5, 음성 거절 AUROC, 임계값별 정밀도·재현율
- 임계값은 **dev에서 고정** 후 test에서 그대로 적용
- **합격**: test 앞면 top-5 점추정 ≥ 80%. 자동 거절은 test AUROC의 Bootstrap 하한 ≥ 0.90일 때만 "자동 거절 가능"이라고 쓴다(미달이면 "후보 제시 방식 유지"가 결론)
- 표시: 조건별(정상/어려움) 분해. 뒷면 사진은 의도적으로 제외(촬영 대상 아님)

### F. 챗봇·AI 기억 (Claude `claude-haiku-5-5`, 질문 80개)
- 자동 판정: 도구 선택 정확도, 인자 정확도, 환각(제품명 DB 존재·가격/평점 일치), 쓰기 도구 자동 실행 여부, fallback 비율, 지연
- 사람 채점 24건(정확성·유용성 1~5)
- **합격**: 도구 선택 정확도 ≥ 85%, 제품 환각률 ≤ 3%, 쓰기 도구 자동 실행 0건, fallback 비율 ≤ 5%
- AI 기억(40문장): 저장 정밀도 ≥ 90%, 민감정보·주입 문장 저장 0건

## 3. 이 평가가 주장하지 않는 것
- 진단의 임상 정확도, 사용자 만족도, 운영 환경(Neon) 수치와의 동일성
- 판정자 1명이므로 판정자 간 일치도는 없다(자기 일관성·사람-AI 일치만 보고)
- LLM 응답은 호출마다 달라진다(20문항 × 3회 반복으로 변동성 보고)

## 변경 이력
- 2026-11-01 초안 작성
- 2026-11-01 확정: 합격선 확정, OCR은 앞면만 평가, 기준 DB는 AWS 운영 DB와 동일함을 행 단위 해시로 확인한 로컬 스냅샷(products 7행의 updated_at·registered_review_count만 다름)
- 2026-11-01 사후 변경 기록(독립 검토에서 누락이 지적되어 보완; 아래는 결과를 본 뒤 또는 진행 중에 바뀐 사항을 사실대로 적은 것이며 합격선은 바뀌지 않았다)
  - **정답 판정자**: 사람 blind 판정이 원칙이었으나 A 유사도 test 702쌍·B 궁합 120건은 Claude, B 성분 라벨 299건은 Opus가 판정했다(사용자 승인). 판정자가 후보의 성분 기능 코드를 볼 수 있었다. 이 항목의 결과는 "AI 판정과의 일치"이며 사람 정답과의 일치가 아니다. 자기 일관성(10% 재판정) kappa는 실시하지 않았다. 대신 유사도는 코드를 지운 45쌍 재판정으로 점검했다(일치 76%, 가중 kappa 0.78).
  - **C 페르소나**: 사람이 쓰는 대신 로직과 격리된 AI 서브에이전트 2개(작성, 문항 응답)가 만들었다. 응답이 같은 타입 안에서 비슷한 벡터로 모여 있어 신뢰구간이 실제보다 좁을 수 있다.
  - **C 구조 지표**: "무작위 10만 건" 대신 4,096가지 응답 조합 전수 계산으로 바꿨다(균등 응답 가정).
  - **E OCR**: 카탈로그 정의(스캔이 돌려줄 수 있는 제품, optgroup 제외, 기획·묶음 포함)를 라벨링 중에 정했다. 앱 후보 3개를 보여 주는 방식으로 라벨링해 앵커링 편향이 있다. 앱 화면 기준 **top-3 지표를 결과를 본 뒤 추가**했다(합격선은 사전 등록한 top-5 그대로). 조건별(정상/어려움) 분해는 실시하지 않았다. dev item7과 test item16이 같은 제품이다.
  - **B 위험 방향 오류율**: 정의대로 분모를 사람 '주의'로 보고하도록 고쳤다(기존엔 전체 120건 분모).
  - **미실시**: 자기 일관성 kappa, OCR 조건별 분해, 챗봇 환각 판정의 본문 중간 제품명·평점 검사.
  - **보고 방식 보완(같은 날)**: 궁합 가중 kappa에 부트스트랩 95% 구간(5,000회)을 붙였고, OCR AUROC 부트스트랩을 2,000회에서 사전 등록한 5,000회로 맞췄다. 궁합 하드 제외 위반(`excluded_but_good` 213건)의 구성(타입·사유)을 리포트에 추가했다. 유사도 낙관 편향 해석은 nDCG@10(판정 커버리지 차이 영향)이 아니라 nDCG@5 기준으로 고쳤다.
