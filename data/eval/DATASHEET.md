# 평가 데이터 데이터시트

PROTOCOL.md 의 평가에 쓴 데이터가 어디서 왔고 어떻게 만들었는지, 무엇이 한계인지를 적는다.

## 공통
- **DB**: 로컬 Postgres 스냅샷. 2026-11-01 AWS 운영 DB와 평가 대상 테이블(products 제외 전부)이 행 단위 해시까지 동일함을 확인했다. `products` 7행(id 481, 712, 2063, 2119, 3547, 281531, 281538)만 `updated_at`·`registered_review_count`가 다르다.
- **고정 seed**: 20261101. 시드·표본 추출·부트스트랩 모두 이 값에서 파생한다.
- **판정자**: 프로젝트 팀원 1명(본인). 단, 궁합 120건은 Claude(아래 B절 참고). 판정 중에는 모델·방식 정보를 보지 않는다(blind). 판정자 간 일치도는 없다.
- **재현성·격리·독립성 점검(2026-11-01)**
  - 재현성: 채점 명령(`similarity/skin_fit/diagnosis/ocr/chat score`)을 다시 돌려 결과 JSON을 비교했다. `env.git_commit`(코드 커밋)만 다르고 지표는 전부 같았다.
  - 격리: 외부 키(CLOVA·Anthropic·OpenAI 등)를 비우고 `localhost` 밖으로 나가는 소켓 연결·DNS 조회를 막은 상태에서 같은 채점 명령을 돌렸다. 모두 종료코드 0이었고 결과 JSON이 위와 같았다(`budget.json`은 이번에 다시 만들지 않은 기존 결과). 즉 녹화·캐시만으로 재계산된다.
  - 독립성(`scripts/eval/independence.py`): 유사도 test 시드 40개와 dev 시드 140개의 교집합은 0이다. **OCR은 교집합이 있다** — dev item7과 test item16이 같은 제품(스킨푸드 캐롯 카로틴 카밍 워터 패드, id 3665·3862)이다. item16은 test에서 1위로 적중했고, 제외하면 test top-1 68%(21/31)·top-3 77%(24/31)·top-5 81%(25/31)로 결론이 바뀌지 않는다. 임계값은 dev에서 고정했으므로 이 중복은 test 지표를 소폭 낙관적으로 만들 수 있다.
  - 유사도 판정 재점검(코드 제거): 판정 풀에 hybrid가 쓰는 성분 기능 코드가 보였다는 지적에 따라, 등급별 15쌍씩 45쌍(seed 20261101)을 코드를 지운 입력으로 새 AI 판정자(Opus, 저장소 접근 없음 — 도구 호출 기록 Read 1·Write 1)에게 다시 판정시켰다. 일치 34/45(76%, Wilson 61~86%), 가중 kappa(제곱) 0.78. 불일치 11쌍은 모두 처음 0 → 재판정 1이고 등급 1·2는 전부 일치했다. 입력·열쇠·결과는 `data/eval/recordings/sim_rejudge_*.csv`. 원본 판정은 바꾸지 않았다.
  - 페르소나 작성 원본: `data/eval/recordings/personas_authored.csv`(에이전트 A), `personas_answers.csv`(에이전트 B).

## A. 유사도
> **판정자 예외(2026-11-01)**: test 702쌍(`similarity_test_pool.csv`)은 **Claude가 판정했다**(사람 정답 아님). 어느 방식이 낸 후보인지 알 수 없도록 `similarity_test_methods.csv`는 판정이 끝나기 전에 열지 않았다. 판정 규칙은 판정 전에 정했다 — 2: 같은 제형·같은 핵심 기능(같은 제품의 다른 옵션·용량 포함) · 1: 같은 용도지만 제형이 다르거나 기능 일부만 일치 · 0: 용도·제형이 다름(선케어는 무기/유기 필터와 제형까지 같아야 2). 분포는 0이 238, 1이 273, 2가 191건. 평가 대상 hybrid의 성분 기능 라벨도 AI가 만들었으므로 완전히 독립적이지 않다.

| 파일 | 내용 |
|---|---|
| `similarity_gold.csv` (dev) | 기존 80 시드, 843쌍. **AI 1명이 판정**. 설정 선택(제형 γ 등)에 쓴 자료라 낙관 편향이 있다 |
| `curated_gold.csv`, `data/seed/similarity_curated.csv` | 조회가 많은 제품 판정 → 서비스 점수 보정에 반영됨. **test 시드에서 제외**(시드·후보 양쪽) |
| `similarity_test_pool.csv` (test) | 위 자료와 겹치지 않는 시드 40개(카테고리별 10개, 고정 seed 추출). 후보 = 방식별 상위 5개의 합집합(hybrid·served·tfidf·평점순·무작위). 행 순서는 섞었고 방식 정보는 `similarity_test_methods.csv`에 따로 있다(판정이 끝나기 전에는 열지 않는다) |
- 등급: 0 대체 불가 / 1 부분 대체(핵심 기능 일부만 같음) / 2 대체 가능.
- 풀 밖 후보는 판정되지 않았으므로 nDCG@10 에서 0 으로 센다(보수적). 풀이 상위 5개라서 nDCG@5·P@5 는 판정 커버리지가 완전하고, nDCG@10 은 아니다 — 리포트에 `cov10`(상위 10개 중 판정된 비율)을 함께 적는다.
- `served` 방식 = DB `similarities` 테이블의 hybrid 행(서비스가 실제로 내는 값, curated 보정 포함). dev 시드에서는 보정이 같은 판정을 쓰므로 **순환**이다 → dev 의 served 수치는 인용하지 않는다.

## B. 궁합
> **라벨 검수 예외(2026-11-01)**: `review_sample.csv` 299행의 `verdict`는 사람 검수가 아니라 **Opus가 성분 이름만 보고 독립 판정한 결과와의 일치도**다(기존 라벨·`labels.csv`는 보여주지 않음, 원본 `recordings/ingredient_label_opus.csv`). 기능 코드 집합이 같으면 `맞음`, 다르면 `불일치`(Opus 값은 `corrected_functions`). 정확도가 아니라 두 Claude 모델의 일치도이며, 둘 다 틀렸을 수 있다.

- `skin_fit_test_pool.csv`: 단일제품 중 모델이 판정 가능한(근거 성분 3종 이상) 제품 40개(카테고리 층화, 고정 seed) × 피부타입 3개(바스락 사막·조심조심 유리구슬·울긋불긋 화산) = 120건. 사람은 전성분 표기와 타입 프로필(5축)만 보고 적합/보통/주의를 적는다. 모델 판정은 파일에 없다.
- **판정자 예외(2026-11-01)**: 이 120건은 판정자(성분 지식 부족)를 대신해 **Claude가 판정했다** — 사람 정답이 아니라 AI 정답이다. 앱의 궁합 결과·`product_skin_fit`은 보지 않고 전성분과 타입 프로필, 일반적인 화장품 성분 지식(자극·알레르겐·각질제거·폐쇄성)만 근거로 했다. 판정 규칙은 판정 전에 정했다: 민감도 높은 타입(유리구슬)은 향료·알레르겐·에센셜오일·변성알코올·레티노이드·강한 각질제거산·유기 자외선차단제 다수면 '주의', 건조한 타입(바스락 사막)은 모델링팩·스크럽·강한 세정제·알코올이면 '주의', 트러블 타입(화산)은 폐쇄성 오일·버터가 앞쪽이면 '주의'. 평가 대상의 성분 기능 라벨도 AI가 만들었으므로 완전히 독립적이지 않다. 사람 검수가 필요하면 표본 30건 이상을 따로 판정해 일치도를 낸다.
- 타입 3개만 쓴 이유: 기피 규칙(알코올·향료·자극)이 가장 크게 갈리는 타입이기 때문. 나머지 5개 타입은 불변식·분포로만 점검하며 일치도는 잰 적이 없다.
- `data/seed/ingredient_functions/review_sample.csv`: 성분 기능 라벨 검수표(299행). `verdict` 열을 사람이 채운다.
- 외부 기준(`data/seed/skin_type_ingredients/criteria.csv`)은 **이전의 피부타입 분류(수부지·트러블·지성…)** 기준이라 현재 8타입과 이름이 맞지 않는다. 판정의 보조 참고로만 쓴다.

## C. 진단
- 문항 6개 × 선택지 4개 = 4,096가지 응답 조합을 전수로 계산한다. 균등 응답을 가정한 구조 지표이며 실제 사용자 분포가 아니다.
- `diagnosis_personas.csv`: 페르소나 30개 + 기대 타입 + 문항 응답. **사람이 아니라 AI(Claude Opus 서브에이전트 2개)가 작성했다.** 에이전트 A는 8타입의 기획서 정의(핵심 특성)만 받아 페르소나 글과 기대 타입을 썼고(타입별 3~4명, 애매한 사람 6명 포함), 에이전트 B는 기대 타입을 가린 페르소나 글과 문항 6개만 받아 선택지를 답했다. 두 에이전트 모두 저장소 파일을 읽지 않았음을 도구 호출 기록으로 확인했다(A: Write 1회, B: Read 1회·Write 1회). 채점 가중치를 본 상태에서 쓰이지 않았고 결과를 보고 고치지 않았다.
  - 한계: 개발자가 쓴 것이 아니라 로직과 격리됐다는 점에서는 독립적이지만, AI가 상상한 사용자라 실제 사용자 분포와 다를 수 있고, 같은 AI 계열이 두 단계를 맡아 사람 작성보다 독립성이 약하다. 기대 타입은 기획서의 한 줄 정의에서 AI가 고른 것이라 그 자체가 정답은 아니다. 팀원이 일부를 직접 쓰면 보강된다.

## D. 추천·예산
- 요청 1,000건을 고정 seed 로 생성(예산·피부타입·무향/무알코올·제외 제품 무작위). 실행 중인 백엔드 API 를 호출한다.
- 품질 지표는 서비스가 최적화하는 `product_skin_fit` 점수를 쓰므로 **독립적인 정답이 아니라 일관성 점검**이다.

## E. OCR
- `data/ocr_test/item{N}_f.jpg` 앞면 48장. dev = item1~11(1024px 축소본, 라벨 있음), test = item12~48(원본 4032×3024 → 앱과 같게 장변 1024px·JPEG q85로 축소해 OCR).
- 뒷면 사진은 의도적으로 평가하지 않는다.
- test 라벨: `data/ocr_test/labels_test.csv` (`in_catalog` Y/N 을 명시한 행만 채점).
- **제품 선택 방식**: 팀원들이 각자 가지고 있던 제품을 찍었다(카탈로그에서 무작위로 고르거나 일부러 카탈로그에 없는 제품을 고른 것이 아님). 따라서 개인이 실제로 소지한 제품 분포를 따르며, 인기 제품·최근 구매 제품에 치우쳤을 수 있고 카탈로그 전체를 대표하지 않는다. 카탈로그에 없는 음성 5건은 의도한 것이 아니라 소지품 중 우연히 DB에 없던 제품이다. 촬영자 수·기기·조명 등 촬영 조건은 기록이 없다(미기재).
- 사진 원본 37장(item12~48, 약 85MB)은 저장소에 올릴 예정이다. 얼굴이나 개인정보가 찍히지 않았는지 올리기 전에 확인한다.
- **정답 라벨 작성 방법(test 37장)**: 앱 스캔 후보 3개를 `labels_test.csv`에 미리 넣어 두고, 라벨러(사용자)가 사진과 상품 링크를 보고 항목별로 판정했다. 후보에 정답이 없으면 제품명·영문명으로 DB를 직접 검색해 넣었고 `source=manual`로 구분했다(`list` 25건, `manual` 12건). `list`가 비어 있던 item16·18·20·21은 후보 열과 정답을 대조해 `list`로 채웠다.
- **카탈로그 정의**: 스캔 `match_text`가 검색하는 활성 제품 전부(`composition='optgroup'` 제외). 앱 목록에는 `single`만 보이지만 스캔은 `bonus`·`bundle`·`goods`도 돌려주므로 정답에 포함했다. 같은 상품의 용량·기획 변종은 앱이 한 후보(드롭다운)로 묶으므로(`group_key`), 후보 안 어느 변종이 나와도 적중이다. 묶음이 다르면 정답 id를 모두 적었다.
- **채점 기준**: 정답 id 중 하나라도 후보(대표+드롭다운)에 있으면 적중. 사전 등록 지표는 top-1/top-5이고, 앱이 후보 3개만 보여 주므로 **top-3을 사후에 추가**했다(`scripts/eval/ocr.py add_top3`).
- **한계**: (1) 라벨러가 후보를 보고 판정해 앵커링 편향이 있다. (2) 음성 5건(item14·22·34·36·37)뿐이라 목표 10건 미달, 거절 성능 신뢰구간이 넓다. (3) 로컬 Postgres 스냅샷으로 평가했다(평가 대상 테이블은 운영 DB와 같음을 공통절대로 확인). (4) 일부 판정에서 사진의 용량·패키지 일치 여부는 라벨러의 시각 판단이다.
- OCR 응답 캐시: `recordings/ocr_service_cache.json` (서비스 경로 `recognize_text` 로 호출, 사진 해시 포함).

## F. 챗봇·AI 기억
- 질문 80개와 기대(도구·인자·금지 행동)는 `scripts/eval/chat_cases.py`에 응답을 보기 전에 적었다. 작성자는 개발자 본인(AI 지원)이다.
- 제품 자리표는 DB 에서 고정 규칙(카테고리별 리뷰 수 1위)으로 채운다.
- 모델: `LLM_CHAIN=claude`, 모델명은 `CLAUDE_MODEL`(기본값). OpenAI 키가 없어 Claude 로만 평가했다.
- 녹화: `recordings/chat_claude.jsonl`, `recordings/memory_claude.jsonl` — 응답 원문·도구 호출 기록. 채점은 녹화만 읽는다.
- 평가 계정은 로컬 DB 에 임시로 만들고 끝나면 삭제했다.
- LLM 채점자는 쓰지 않았다(평가 대상이 Claude 이므로 자기 채점이 된다).
