## 왜 더 파봐야 효과가 적은가

1. **실패 원인이 이미 진단됨** — FSRCNN으로 해상도를 올려도 결과가 소수점까지 동일했다.
   즉 실패하는 사진들은 "화질이 낮아서"가 아니라 **블러·저대비·필기체처럼 사진 자체에
   정보가 없는 케이스**다. 어떤 OCR 엔진을 갖다 붙여도 없는 정보를 만들어낼 수는 없다.
2. **매칭 기준이 이미 관대함** — identification_score는 정확히 일치해야 점수를 주는 게
   아니라 trigram 유사도 임계값만 넘으면 인정하는 퍼지 매칭이다. 그런데도 44.4%가 완전
   실패라는 건, 텍스트 인식 정확도의 문제가 아니라 애초에 텍스트 자체가 안 잡힌다는 뜻.
3. **더 무거운 로컬 모델은 오히려 손해** — Surya·PaddleOCR-VL처럼 "정확도가 더 높다"고
   알려진 모델들은 이 하드웨어(GPU 미지원)에서 속도가 100배 느려지는 대가를 치른다.
   남은 후보(Qwen2.5-VL)도 같은 함정일 가능성이 크다.
4. **아직 검증 안 된 지표를 올리는 것 자체가 시기상조** — 지금 나온 숫자는 전부 정답
   CSV 대상 대리 지표고, 실제 4,150개 제품 DB 매칭(Task 4.4)은 한 번도 안 해봤다. 진짜
   병목이 OCR 정확도인지 DB 매칭 로직인지조차 아직 모르는 상태에서 OCR만 더 파는 건
   우선순위가 안 맞는다.

## 결론

CLOVA + region-detection으로 엔진 확정. 남은 시간은 다음 두 가지에 쓰는 게 더 생산적:

- **Task 4.4** — OCR 결과를 실제 PostgreSQL `products` 테이블(4,150개)에 매칭해 진짜
  성공률 검증 (pg_trgm `similarity()` 재사용, 새 의존성/연결 코드 불필요)
- **수동 검색 폴백 UI** — 완전 실패(44.4%) 케이스를 위한 사용자 경험 설계
