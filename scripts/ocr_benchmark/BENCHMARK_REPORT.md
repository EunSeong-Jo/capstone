# OCR 3종 벤치마크 결과 보고서 (Tesseract vs EasyOCR vs PaddleOCR)

## 배경

Task 4(이미지 인식 모듈)의 실제 구현에 들어가기 전, 어떤 OCR 엔진을 채택할지 결정하기 위한
선행 실험이다. PRD(`docs/PRD_대체뭐야_v1.8.md` §7.5)는 Tesseract + EasyOCR 조합만 명시했지만,
오픈소스·한글 지원·GPU 불필요 조건에 맞는 PaddleOCR을 세 번째 후보로 추가해 3종을 비교했다.

PRD상 OCR 모듈의 실제 역할은 **사진 속 브랜드명/제품명만 인식해 DB와 fuzzy-match(pg_trgm)하는 것**이며,
전성분 리스트는 OCR이 아니라 이미 수집된 DB 데이터(Task 2)에서 가져온다. 이번 벤치마크도 이 범위에
맞춰 "브랜드명+제품명 인식률"을 기준으로 진행했다.

## 진행 과정

1. **환경/파이프라인 구축** — `scripts/ocr_benchmark/`에 독립 실험 폴더 구성. Python 3.11 conda 환경(`ocr_bench`),
   OpenCV 전처리(EXIF 보정 → 리사이즈 → CLAHE 명암 정규화 → 디노이즈), 3개 엔진 실행 모듈, 지표 계산 모듈,
   라벨링 템플릿 생성기를 구현.
2. **테스트 이미지 확보 및 검수** — 보유 중이던 화장품 패키지 사진 45장을 투입. 검수 과정에서 완전 중복 파일
   4쌍을 발견해 제거(41장), 제품명이 프레임에 없는 이미지 1장을 표시. 최종 38장으로 라벨링 진행.
3. **정답 라벨링** — 파일명 기반 힌트를 자동 생성한 뒤, 사진을 직접 보고 브랜드명+제품명을 `ground_truth`에
   입력하는 방식으로 38장 전체 라벨링 완료. (라벨링 과정에서 CSV 인코딩이 CP949로 저장되어 UTF-8로 재변환하는
   이슈가 있었음.)
4. **1차 실행 및 지표 오류 발견** — 첫 벤치마크 실행 결과 CER이 비정상적으로 높게(8~26) 나옴. 원인 분석 결과,
   각 엔진이 이미지 전체 텍스트(전성분표 포함, 수백~수천 자)를 추출하는데 이를 수십 자짜리 정답과 통째로
   비교해 지표가 왜곡된 것으로 확인. → **줄 단위 조각 중 정답과 가장 가까운 조각을 찾아 비교하는
   best-fragment 매칭 방식으로 지표 계산 로직을 수정**하고 재실행.
5. **결과 분석 및 이중언어 라벨 보정** — 정답에 "영문명 (한글 번역)" 형태로 병기된 항목들이 실제 사진엔 한
   언어만 찍혀있어 CER이 과대평가되는 것을 발견, 정답을 영문/한글/전체 3가지 후보로 나눠 가장 가까운 쪽으로
   재계산. 실패 케이스 18건을 이미지별로 직접 대조해 원인을 4가지 패턴으로 분류.

## 결과 요약 (38장, best-fragment + 이중언어 보정 기준)

| 엔진 | 평균 CER | 좋은 매치(CER<0.3) | 정확 일치 | pg_trgm 임계값(0.3) 통과 | 평균 처리시간 |
|---|---|---|---|---|---|
| **EasyOCR** | **0.639** (최저) | 5/38 | 1/38 | **8/38 (21%)** (최고) | 22.6초 |
| PaddleOCR | 0.738 | 0/38 | 0/38 | 7/38 (18%) | 32.5초 (최느림) |
| Tesseract | 0.787 | 4/38 | **2/38** (최다) | 5/38 (13%) | **15.5초** (최빠름) |

- **평균 정확도·안정성 기준으로는 EasyOCR이 가장 우수**하다. 완전 실패(빈 결과)가 0건이고, "실전 매칭 성공
  가능성"에 가까운 pg_trgm 통과율도 가장 높다.
- Tesseract는 맞힐 때는 가장 정확하지만(정확 일치 2건, 최다), **38장 중 13장(34%)에서 텍스트를 아예 하나도
  추출하지 못했다** — 이 극단적인 양상 때문에 "그럭저럭 비슷하면 되는" 실전 기준에서는 오히려 순위가 밀린다.
- PaddleOCR(2.9.1, PP-OCRv3/v4 다국어 모델)은 이번 데이터셋에서 가장 느리고 가장 부정확했다.

## 실패 원인 분석 (18/38장, 3개 엔진 모두 CER>0.7)

1. **Tesseract의 완전 실패(34%)** — `raw_text`가 아예 빈 문자열인 경우가 13/38장. EasyOCR·PaddleOCR은
   완전 공백 0건으로, 뭐라도 추출은 하지만 오인식하는 차이가 있다.
2. **배경 노이즈를 텍스트로 착각(환각)** — 나뭇결·배경 패턴을 의미 없는 한글 음절 나열로 잘못 인식하는 사례
   (예: `IMG_3069.png`에서 EasyOCR이 189자짜리 무의미한 텍스트를 생성).
3. **엉뚱한 영역 인식** — 제품명 대신 로트번호, "MADE IN KOREA" 같은 부차적 텍스트를 최적 후보로 선택.
4. **사진에 제품명이 아예 없음** — 성분표만 클로즈업된 사진 1건은 애초에 정답을 맞힐 수 없는 케이스.

이 중 1~3번은 **텍스트 영역 검출(브랜드/제품명 영역만 먼저 크롭) 없이 이미지 전체를 OCR에 넣기 때문**에
발생하는 문제로 보인다. PRD가 원래 계획한 EAST/CRAFT 텍스트 영역 검출 단계가 왜 필요한지를 실증적으로
보여준 결과다.

## 성능 개선 방법 (우선순위 순)

1. **텍스트 영역 검출 도입 (최우선)** — PRD가 계획한 EAST/CRAFT 기반 브랜드/제품명 영역 검출을 OCR 이전
   단계에 추가. 지금의 실패 사례 대부분(엉뚱한 영역 인식, 배경 노이즈 오인식)을 직접적으로 해결할 가능성이 큼.
2. **Tesseract PSM(페이지 분할 모드) 조정** — 기본 모드(PSM 3, 문서 전체 가정) 대신 `--psm 11`(sparse text)
   또는 `--psm 6`으로 변경. 코드 한 줄 수정으로 시도 가능한 저비용 개선이며, 완전 실패 비율(34%) 감소가
   기대됨.
3. **작은 텍스트 업스케일** — 현재 전처리는 1280px 다운스케일만 수행. 텍스트 영역 검출 후 해당 크롭만
   2~3배 확대해서 OCR에 넣으면 작은 브랜드 로고 텍스트의 인식률 개선 가능.
4. **Tesseract → EasyOCR 하이브리드(Fallback)** — PRD가 이미 계획한 "인식 실패 시 Fallback" 구조를 그대로
   활용. Tesseract를 먼저 시도(빠름) → 결과가 비었거나 신뢰도가 낮으면 EasyOCR로 재시도. 속도와 안정성을
   함께 확보하는 방향.
5. **PaddleOCR 모델 업그레이드 검토** — 현재 pin된 `paddleocr==2.9.1`(PP-OCRv3/v4)에서 최신 3.x(PP-OCRv5)로
   올리면 개선 가능성 있음. 단, API가 크게 바뀌어(`ocr.ocr()` → `predict()`) 별도 검증 필요.
6. **라벨셋 품질 개선** — 다음 라벨링부터는 `ground_truth`에 실제 사진에 보이는 언어 하나만 입력하고,
   참고용 번역은 `notes` 칸으로 분리하여 지표 왜곡을 원천적으로 방지.
